# CI

1. A Windows machine does not show what the Linux and macOS runners show: build tags, file-system case, `unix.Statfs_t` field types, Bun versus Node behaviour. Run the cross-target lint of `skills/ci-preflight/` before a change that touches paths, file systems, processes or build tags is handed off.
2. While the epics are implemented, by the author's decision on 2026-11-18 (ADR-0045), CI is not a gate: `main` was red on that date and its ruleset `protect-main` is disabled. The evidence of a change is the local checks of `AGENTS.md` section 9, run by the engineer and again by the specialist. Do not delete or weaken a workflow to make a run green: the workflows are repaired release by release when the integration pull request is split. `installers.yml` is also called by `release.yml` through `workflow_call`: check after each release that its jobs ran.
3. Timing asserts skip under `-race` (`raceEnabled` constants in `*_race_test.go` and `*_norace_test.go`). A test that needs more time under the race detector gets more time there, not a looser limit everywhere.
4. A flaky test is a defect. Find the cause (CPU count, SIMD, load, ordering). Never skip it, retry it (a rerun loop, `retries:`, `-count=N` until green) or add a sleep to it; wait on a condition, never on a duration. With no cause found, delete it in its own commit that says why. `skills/verify/scripts/check-flaky-patterns.sh` refuses those patterns in added lines; an environment skip (an OS, a privilege, a missing tool) carries `verify:env-skip <reason>`.
5. A failing check whose cause is a real bug of the product is fixed in the product, not in the test. `TestSecurity_T12` on macOS was a `filepath.Rel` case bug, not a runner quirk.
6. In a matrix, an `include` entry whose keys are not dimensions is added to every combination and overwrites the entry before it, so a list of `{target, pkg}` includes over `os` runs only the last target. Make the varying key a dimension (`target: [...]`) and let `include` add only what depends on it (`pkg`). `actionlint` does not catch this.
7. Every downloaded input of a build is pinned by URL and SHA-256 measured from a real download, not copied from a page. GitHub's auto-generated archives (`/archive/refs/tags/...`) are not guaranteed byte-stable: prefer release assets, or files pinned to a commit (`raw.githubusercontent.com/<owner>/<repo>/<commit>/<path>`), each with its own digest. The first run of `ffmpeg-build.yml` failed on a wrong OpenH264 tarball pin.
8. A workflow that exists on `main` can be dispatched on another ref (`gh workflow run <file> --ref release/vX.Y.Z -f publish=false`) to test a fix before the release merges. Dispatch with publishing off first; publish only after a green run.
9. Build scripts run on macOS bash 3.2: with `set -u`, an empty array is unbound. Expand possibly-empty arrays as `${arr[@]+"${arr[@]}"}`.
