# Screen reader checklist of the editor

The manual pass of SDD-012 section 18.4 item 4 (RF-075, task P3-QA-002). It is part of the BETA sign-off and is not run in CI: the automated checks (`a11y-axe-both-themes`, `keyboard-only-edit`, `wcag22`) cannot tell what a screen reader says.

One row is one task a person does in the editor. Run every row with every reader of the matrix, write the outcome in a file made from `results/TEMPLATE.md` (one file per run and reader, see `results/README.md`), and file a card for each failure (see "Filing a failure").

`Mod` is `Ctrl` on Windows and `Cmd` on macOS. The names the readers must say come from the catalogue (`ui.editor.*`), so the examples below are the English text; run a second pass with the language set to pt-BR before the sign-off, and check that the spoken names are translated and not mixed.

NF and NC are `n/a` for them (the shell has no Firefox or Chrome), Narrator runs them against WebView2 and VoiceOver against the macOS shell (WKWebView). The dialogs are native, so the spoken text is the one of the system dialog.

## How to set up

1. Use a clean profile or a private window and the default zoom (100%). Start the product the way the pass needs it (local mode, `stuarty` serving a project with a video clip, an audio clip, a caption track with five or more words and a marker, so every row finds its target). Use the same project for every reader.
2. **NVDA.** Install the stable release from nvaccess.org. Open the speech viewer (`NVDA menu`, `Tools`, `Speech viewer`) and keep it visible: it is the record of what was said, and the text copied from it goes into the notes. `Insert+Space` switches between browse mode and focus mode (NVDA also switches by itself when focus enters a field or a widget); an announcement of "focus mode" or "browse mode" is not a failure. `Insert` is the NVDA key (`Caps Lock` when the laptop layout is on). `Insert+Tab` says the focused element again.
3. **Narrator.** `Win+Ctrl+Enter` starts and stops it. `Caps Lock` is the Narrator key. `Caps Lock+Tab` says the focused element again. Turn on "Show Narrator highlight" so the focus is visible.
4. **VoiceOver.** `Cmd+F5` starts and stops it. `Ctrl+Option` is the VoiceOver key. In Safari turn on `Settings`, `Advanced`, "Press Tab to highlight each item on a webpage" and set "Use the keyboard to move between controls" (`Full Keyboard Access`), or the grid and the buttons are not reachable with `Tab`. Open the VoiceOver caption panel (`VoiceOver Utility`, `Visuals`, "Show caption panel") to read what was said.
5. Do not use the mouse. Move with `Tab`, `Shift+Tab`, `F6` (next landmark) and the keys of the row. Reader commands to read the page (`NVDA+Down`, `VO+A`) are allowed, and the row says when the focus must have moved.
6. Write down the name and the version of the reader, the browser, the system and the product version in the header of the results file.

## What a row asks

- **Keys.** What to press, from the state named in the row.
- **Must announce.** The role, the accessible name, the state and the value that the reader must say, in the words of the catalogue. A reader may order the words differently ("Split button" or "button Split"); a missing role, name, state or value is a failure, and so is a name that reads a file name or an identifier instead of a word.
- **Focus lands.** The element that has the focus after the keys. Focus must be visible on screen (SDD-012 section 18.1 item 6) and must never be lost to the page body.
- **Results.** One cell per reader of the matrix, `-` until the row is run. In the results file the cell is `pass`, `fail` with the number of the card, `n/a` or `todo`.

## Filing a failure

A failure is a row and a reader where any of "Must announce" or "Focus lands" is not met. For each failure:

1. Open a card (an issue in the repository tracker or a new `VV-NNN` entry of the issue queue, as the team uses at that time) with the title `a11y(<area>): <reader> does not <what>`, for example `a11y(timeline): NVDA with Firefox says "clickable" for the clip cell`.
2. In the body write the row id (`SR-04`), the reader and its version, the browser and its version, the product version, the exact keys, what was said (copy it from the speech viewer, the Narrator history or the VoiceOver caption panel, verbatim), what should have been said and where the focus went. Add a screenshot or a short recording of the speech viewer when the text alone is not enough.
3. Reference SDD-012 section 18.1 (or 18.2, or the section of the row) and say if it is a spoken-name problem (fix in the catalogue or in the `aria-label`), a role or state problem (the component), or a focus problem (the dialog or the action).
4. Write `fail #<number>` in the cell of the results file, with the number of the card. A row with `fail` and no number is incomplete, and so is a cell left as `todo`.
5. After the fix, run the row again with the reader that failed and every reader that shares the component, and replace the cell with `pass` and the date in the notes.

A difference between readers that is only wording ("button Split" and "Split button") is not a failure. A difference in what is said (a missing name, a state said as a different one) is. When the readers disagree about a correct element, open one card, name both readers and say which one follows the specification.
