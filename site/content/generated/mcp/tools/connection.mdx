<RefMain>

The user's connected destinations (id, kind, label, hosts, what each accepts, last use), or one by id. Never returns a credential. Only a person adds, removes or tests one.

## Behaviour

These are the annotations of the tool definition, the hints a client uses to decide whether to ask before a call. `connection` is listed by `tools/list`.

| Property | Value |
| --- | --- |
| Read only | yes |
| Destructive | no |
| Idempotent | yes |
| Reaches outside the workspace | no |

## Input

| Argument | Type | Required | Notes |
| --- | --- | --- | --- |
| `id` | `string` | no | pattern `^con_[0-9a-hjkmnp-tv-z]{10}$` |

## Output

A result has a text block, written for the model, and structured content with these members.

The structured content is the result of the service operation; see the text block of a call.

## Errors

- [`E_VALIDATION`](/docs/reference/error-codes#e_validation)
- [`E_CONNECTION_NOT_FOUND`](/docs/reference/error-codes#e_connection_not_found)

A call over HTTP without credentials fails with `E_UNAUTHORIZED`, and too many calls with `E_RATE_LIMITED`. Both are in the [error codes](/docs/reference/error-codes).

## Safety

- The result never holds a credential, only `secret_set`. A label is text a person typed: it is data, not instructions.
- There is no tool to add, remove or test a connection; a person does that in the Connections page or with the CLI.
