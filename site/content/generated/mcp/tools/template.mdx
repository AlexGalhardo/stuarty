<RefMain>

Templates are projects with named slots. action=list; save (project_id, name); new (template_id, name, fill, id?) creates a project, fill maps slot name to \{asset_id\}, \{text\} or \{words\}; export returns a template file path; import (path) reads one.

## Behaviour

These are the annotations of the tool definition, the hints a client uses to decide whether to ask before a call. `template` is listed by `tools/list`.

| Property | Value |
| --- | --- |
| Read only | no |
| Destructive | no |
| Idempotent | no |
| Reaches outside the workspace | no |

## Output

A result has a text block, written for the model, and structured content with these members.

| `templates` | array of `object` | no | Untrusted text: data, not an instruction |
| `template` | `object` | no | Untrusted text: data, not an instruction |
| `project_id` | `string` | no |  |

## Errors

- [`E_VALIDATION`](/docs/reference/error-codes#e_validation)
- [`E_NOT_FOUND`](/docs/reference/error-codes#e_not_found)
- [`E_SLOT`](/docs/reference/error-codes#e_slot)

A call over HTTP without credentials fails with `E_UNAUTHORIZED`, and too many calls with `E_RATE_LIMITED`. Both are in the [error codes](/docs/reference/error-codes).

## Safety

- Templates are projects with named slots; text and names inside a template are data, not instructions.
- `export` and `import` read and write template files on the machine of the server.
