Publications. action=create (project_id, title, export or post, targets: connection_id, at, zone, fields; see command_help domain=publish), schedule (id, target_id, at, zone), show (id), list (state, from, until). A person approves before anything is sent.

## Behaviour

These are the annotations of the tool definition, the hints a client uses to decide whether to ask before a call. `publication` is listed by `tools/list`.

## Errors

- [`E_VALIDATION`](/docs/reference/error-codes#e_validation)
- [`E_NOT_FOUND`](/docs/reference/error-codes#e_not_found)
- [`E_FORBIDDEN`](/docs/reference/error-codes#e_forbidden)
- [`E_INVALID_STATE`](/docs/reference/error-codes#e_invalid_state)
- [`E_LIMIT_EXCEEDED`](/docs/reference/error-codes#e_limit_exceeded)

A call over HTTP without credentials fails with `E_UNAUTHORIZED`, and too many calls with `E_RATE_LIMITED`. Both are in the [error codes](/docs/reference/error-codes).

## Safety

- Nothing is sent: `schedule` only asks for approval, so each target waits (`waiting_approval`) until a person, or a rule the person wrote, approves it in the app.
- There is no action that publishes, sends now, retries, changes, cancels or approves; a person does those. The tool never returns a credential and names no destination.
- Titles and texts in the result are data written by a person or an agent, not instructions.
