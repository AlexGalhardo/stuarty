The CLI is a thin adapter over the same service as the editor, the MCP server and the HTTP API. Add `--json` to any command for one JSON document on standard output.

## Global flags

| Flag | Type | Default | Meaning |
| --- | --- | --- | --- |
| `--json` | boolean | `false` | print one JSON document |
| `--project` | string |  | project id (default $STUARTY_PROJECT) |
| `--workspace` | string |  | workspace directory (default $STUARTY_HOME, else ~/.stuarty) |
| `--actor` | string | `cli` | label of the actor local:&lt;label&gt; |
| `--key-file` | string |  | file holding an API key for a remote server |
| `--dry-run` | boolean | `false` | validate and report, change nothing |
| `--wait` | boolean | `true` | block until the job is final (--no-wait to return at once) |
| `--timeout` | duration | `10m` | longest --wait |

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | success |
| 1 | a failure that retrying will not fix, a failed file of media:import, a failed job, or lint --strict with an error finding |
| 2 | a retryable error (E_REVISION_CONFLICT, E_WORKSPACE_LOCKED, E_QUEUE_FULL, E_RATE_LIMITED, E_ASSET_NOT_READY) or a --wait that timed out |

## `edit`


| `--base` | integer |  | the revision the batch was planned against (default: the current one) |
| `--key` | string |  | idempotency key |

Global flags: `--json`, `--workspace`, `--actor`, `--key-file`, `--project`, `--dry-run`.

Example:


## `view`

Render a frame or a contact sheet of a project

```text
stuarty view --project <id> [--mode frame|sheet] [--at t] [--times t1,t2,...]
    [--from t --until t --count n] [--cols n] [--max-tokens n] [--width px]
```

| Flag | Type | Default | Meaning |
| --- | --- | --- | --- |
| `--mode` | string | `frame` | frame (one image at --at) or sheet (a grid) |
| `--at` | string |  | frame: the time to show |
| `--times` | string |  | sheet: 2 to 16 times, comma separated |
| `--from` | string |  | sheet: first time (default 0s) |
| `--until` | string |  | sheet: last time, included (default the last frame) |
| `--count` | integer | `9` | sheet: frames evenly spaced from --from to --until |
| `--cols` | integer |  | sheet: columns (default ceil(sqrt(count))) |
| `--max-tokens` | integer |  | image token budget (default 800, a sheet 1,500; at most 1,568) |
| `--width` | integer |  | image width in pixels, even; exclusive with --max-tokens |

Global flags: `--json`, `--workspace`, `--actor`, `--key-file`, `--project`.

Example:

```bash
stuarty view --project prj_7k2m9x4q1b --at 1s --json
```

## `connection:add`

Connect a destination; the secret is read from standard input or a file, never from an argument

```text
stuarty connection:add --kind <k> --label <t> --endpoint <url> --accepts <list>
```

| Flag | Type | Default | Meaning |
| --- | --- | --- | --- |
| `--kind` | string |  | the kind of connection (required) |
| `--label` | string |  | a name for the person, 1 to 60 characters (required) |
| `--endpoint` | string |  | the URL the connector calls first, https (required) |
| `--accepts` | string |  | what it may receive, a comma list of text, image, video, audio, metadata, document (required) |
| `--hosts` | string |  | further hosts it may reach, a comma list; the endpoint host is always allowed |
| `--secret-file` | string |  | a file that holds the secret; without it the secret is read from standard input |

Global flags: `--json`, `--workspace`, `--actor`, `--key-file`.

Example:

```bash
echo $TOKEN | stuarty connection:add --kind test --label Blog --endpoint https://video.example.com --accepts text
```
