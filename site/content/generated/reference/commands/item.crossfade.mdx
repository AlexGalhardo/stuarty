The item that leaves gets a fade transition out and the item that arrives a fade transition in, both of the given length, plus the matching audio fades for clips. The two items must overlap by at least that length, and the arriving item must start after the leaving one. For two neighbours that touch on the same track give track_id, another visual track: the arriving item moves there and starts duration earlier, using the source it has before the cut, so they overlap by duration.

## Arguments

| Argument | Type | Required | Description |
| --- | --- | --- | --- |
| `duration` | `string` | yes | Length of the crossfade, at least 1 frame. |
| `from_item_id` | `string` | yes | The item that leaves. |
| `to_item_id` | `string` | yes | The item that arrives. |
| `track_id` | `string` | no | Only for two neighbours that touch on one track: another visual track the arriving item moves to. |

## Example

As one operation of an `edit` batch (the `edit` tool of MCP, `vukem-video edit --ops`, or `POST /api/v1/projects/{id}/edit`):

```json
{
  "op": "item.crossfade",
  "args": {
    "duration": "1s",
    "from_item_id": "itm_m1n2p3q4r5",
    "to_item_id": "itm_s6t7v8w9x0"
  }
}
```
