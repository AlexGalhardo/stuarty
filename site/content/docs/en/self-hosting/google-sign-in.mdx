## You will learn

- what the optional Google sign-in does, and what it never does;
- how to set up your own Google project, the redirect address and the scopes it needs;
- how a user links their Google account, and how you turn the feature on, restrict it and turn it off.

## The idea

On a server in [network mode](/docs/self-hosting/network-mode) people sign in with an email and a password. You may also let them sign in with a Google account. It is **optional and off by default**; on the desktop, in local mode, no login is asked and none of this exists.

- A Google account is **linked** by a user who is already signed in, from Settings, with their password. Afterwards "Sign in with Google" opens that user's session, the same session a password login opens.
- There is **no registration with Google**. A Google account that nobody linked is refused with a clear message, even when its e-mail is the one of a local user: accounts are matched by Google's stable subject identifier, never by e-mail.
- The password login always keeps working, so losing the Google account never locks anyone out. Unlinking changes nothing else.
- Stuarty stores only that identifier and the e-mail. The server never keeps an ID token or an access token.
- It uses a **Google project that you own**. There is no Stuarty account and no central service. With the feature off, the server opens no connection to Google.

## Set it up

1. In the [Google Cloud console](https://console.cloud.google.com/apis/credentials) create an OAuth client of type "Web application" in a project you own (the same one you made for YouTube works). Google lets a project whose owner is its only user skip verification; a project in "Testing" status limits the users to those you list there.
2. Add this as an **authorised redirect URI**: your `APP_URL` followed by `/login/google/callback`, for example `https://video.example.com/login/google/callback`. Settings, "Google sign-in", shows the exact address. If you also publish to YouTube, keep the redirect address of that guide as well.
3. The scopes are `openid` and `email`. Nothing else is asked.
4. In Stuarty, open **Connections** and add the YouTube connection with the client id and the client secret of the project. You do not need to complete the YouTube sign-in. The secret goes into the encrypted vault.
5. Open **Settings, Google sign-in** as an administrator, choose that connection, tick "Let users sign in with Google" and save. Optionally list the Google e-mail addresses that may use it: one per line; empty means every linked user.

## A user links their account

1. Sign in with the password, open **Settings, Google sign-in**, type the password again and press "Link my Google account".
2. Choose the account at Google. You come back linked.
3. Next time the login page shows "Sign in with Google".

To remove the link, press "Unlink" (the password is asked again).

## Turn it off

Untick the box and save: new Google sign-ins stop at once, sessions already open are not touched, and the server opens no connection to Google.

## Common mistakes

- The redirect address in the Google project differs from the one Settings shows (scheme, host, port or path): Google refuses the sign-in before it reaches Stuarty.
- A project in "Testing" status whose test users do not include the person.
- Expecting Google to create the user: the user must exist and link first.
- An address on your list that differs from the Google account's e-mail.
