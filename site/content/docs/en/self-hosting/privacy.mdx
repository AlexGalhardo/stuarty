## You will learn

- that a default run makes no outbound connection;
- the full list of exceptions, and who controls each;
- what the product does not have.

## The idea

With the default settings the binary opens **no outbound network connection**. There is no telemetry, no update check (the desktop application has one, which asks your consent first), no crash reporting, no font or icon service and no analytics. The editor's assets are embedded, and its security policy lets the page reach only the server it came from. A test starts the server with every setting unset, runs a full create, import, edit, export and verify, and fails on any connection; a CI job repeats the run with the real binary and FFmpeg and watches for connections on Linux.

A connection **to** the server, from a browser or a client you use, is inbound and not counted here.

| Path | Opens a connection when | To | Default |
| --- | --- | --- | --- |
| Transcription API | `STUARTY_TRANSCRIBE_URL` and `STUARTY_TRANSCRIBE_KEY` are set and a transcription runs | the host you configured, with the audio of one asset and the key | off |
| Helper download | a person runs `tools:install` or presses Install in the editor | the hosts of the embedded manifest | never at run time |
| OpenTelemetry | `OTEL_EXPORTER_OTLP_ENDPOINT` is set | that endpoint | off |
| Desktop update check | you answered Yes to the first-use question, or you choose **Help**, **Check for updates** | `video.vukem.dev`, one signed file, nothing about you | asked once; nothing connects before the answer |
| CLI and stdio MCP as clients | a server owns the workspace | the loopback address of that server, or `STUARTY_URL` when you set it | loopback only |
| Browser launch | `serve` opens your browser | your browser connects to loopback; the product makes no connection | loopback only |
| AI provider | you create a connection to one (an API key, Sign in with ChatGPT, OpenRouter) and a draft, an image, a voice or a model operation uses it, after your approval when it costs money | the host of that connection, with the prompt and what you chose to send (a picture, a text), and your key | off until you connect one |
| Social network | you create a connection with your own developer app, sign in, and approve a post | the hosts of that network (the page of each network lists them), with the video, the text and the thumbnail you approved | off until you connect one |
| Your local agent | you connect it as a provider | nothing leaves the machine: it runs on your side | off until you connect one |
| Google sign-in | on a server in network mode where you turned [Google sign-in](/docs/self-hosting/google-sign-in) on, a person signs in with Google or links a Google account | the hosts of the connection you chose (`oauth2.googleapis.com` and `www.googleapis.com`), for the code and the keys; the browser, not the server, opens Google's sign-in page | off |

That is the whole list. The transcription provider receives only the normalised audio of the asset and the key. It receives no project, no file name and no path, the certificate is always verified, redirects are refused and the job says which host receives the audio. The helper download is announced with its size and host before it starts.

No tool of an agent can make the product send data to an address of its own choosing: no argument is a URL, host, webhook or destination, and there is no import by URL. What an agent can reach is only the destinations you connected, and publishing and costly generation wait for you in the [approval queue](/docs/guide/approvals). FFmpeg, ffprobe and the transcription program are never given a network address; on Linux, `STUARTY_SANDBOX=bwrap` makes the operating system enforce it.

## Quick start

To verify it on your own machine, run the server and watch its connections with the tool of your system. On Linux:

```bash
stuarty serve &
ss -tnp | grep stuarty
```

You should see only the listening socket and your own browser. Stop the server with `kill %1` when you finish.

## Common mistakes

- Setting a transcription URL without understanding that the audio goes there. Use a host you control, or leave it unset and use local transcription.
- Treating `OTEL_EXPORTER_OTLP_ENDPOINT` as harmless: it sends request traces to that endpoint.
- Running `tools:install` without reading what it prints: it names the host and the download size before it asks you to continue.
