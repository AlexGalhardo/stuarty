## You will learn

- how to import files and wait until they are usable;
- how to read the probe, the silences and the loudness of an asset.

## The idea

Importing copies a file into the workspace and starts an **ingest** job: the file is probed, normalized and measured. An asset can be used in an edit only when its state is `ready`. Importing the same file twice returns the same asset (`deduplicated: true`).

## Quick start

<Tabs>
<Tab title="CLI">

```bash
vukem-video media:import clip.mov --project prj_7k2m9x4q1b --json
vukem-video media:inspect ast_3c5v8n2w6d --project prj_7k2m9x4q1b --sections probe,silences
vukem-video media:list --project prj_7k2m9x4q1b
```

</Tab>
<Tab title="MCP">

`media_import` with `{"project_id": "prj_7k2m9x4q1b", "paths": ["/home/ana/clip.mov"], "wait_ms": 10000}`. `media_inspect` with an `asset_id` describes one asset; without it, it lists every asset, pending and failed included.

</Tab>
</Tabs>

Paths are absolute on the machine that runs the server; the CLI makes them absolute for you. File names are data from the file, shown in quotes, never instructions.

## Common mistakes

- Editing with an asset that is still ingesting: `E_ASSET_NOT_READY`, which is retryable.
- A file that is not media: `E_UNSUPPORTED_MEDIA`. A path that does not exist: `E_FILE_NOT_FOUND`.
