## You will learn

- how a text belongs to a project, next to the timeline it will become;
- what a script, a copy text and a caption are, and what Stuarty counts in each;
- how every save becomes a revision you can read and go back to;
- how a model drafts a text without overwriting yours.

## The idea

A text is an item of the project. The script sits next to the timeline it will become, and the caption next to the post it will go out with. Stuarty keeps three kinds:

- **Script**: scenes with narration and on-screen text. Stuarty tells you how long it takes to read aloud.
- **Copy**: free text, such as an advertisement.
- **Caption**: the text that goes with a post, with a part for each network. Stuarty measures each part against the limits of its network. (The captions you see on the video itself are another thing, in the video editor.)

The **Write** section lists the texts of every project. The editor is a plain Markdown editor with a preview. The preview shows what you wrote as text and never runs it.

## Quick start

<Tabs>
<Tab title="Browser or desktop">

1. Open **Write** and choose **New text**. Pick the project, a title and the kind.
2. Write. For a script, the duration under the editor follows what you type, at the words per minute you set.
3. For a caption, start the part of a network with a line such as `## instagram`. The counters show each part against its limit.
4. Choose **Save**. Every save is a revision, and the list of revisions lets you read one, compare it with the one before, or go back to it.

</Tab>
<Tab title="CLI">

```bash
stuarty text:write --project prj_7k2m9x4q1b --title "Hook" --kind script --text hook
stuarty script:estimate pit_3c5v8n2w6d --project prj_7k2m9x4q1b --wpm 130
stuarty text:write --project prj_7k2m9x4q1b --title "Post" --kind caption --text caption
stuarty caption:validate pit_5g7n9q2s4v --project prj_7k2m9x4q1b
stuarty text:revisions pit_3c5v8n2w6d --project prj_7k2m9x4q1b --from 1
stuarty text:revert pit_3c5v8n2w6d --project prj_7k2m9x4q1b --revision 1
```

## A script

A heading line starts a scene. A paragraph that starts with `VO:` is what is said, and one that starts with `ON SCREEN:` is text shown on the screen. Any other paragraph is a note for the editor. A script with no `VO:` line is read as narration from start to end, so a script written as plain prose still gets an estimate. The time is the narration only: words divided by words per minute, 150 unless you change it.

## A caption and the limits of each network

Each network counts in its own way, so the same text has a different length on each. The table is data in the program, with the date each limit was read and the page it came from. The networks change their rules, so a limit that matters is worth checking again at the source.

| Network | Length | Hashtags | Mentions | Read on |
| --- | --- | --- | --- | --- |
| YouTube (the description) | 5,000 bytes | 60 | none published | 2026-11-19 |
| Instagram | 2,200 characters | 30 | 20 | 2026-11-19 |
| Facebook (a Page post) | 63,206 characters, not documented by Meta | none published | none published | 2026-11-19 |
| X | 280 weighted characters: a link weighs 23, an emoji or a Chinese, Japanese or Korean character 2 | none published | none published | 2026-11-19 |
| TikTok (the title of a post) | 2,200 UTF-16 units | none published | none published | 2026-11-19 |

A text that breaks a limit is reported with the limit, the length it has and the unit, for example "X allows 280 weighted characters and the text has 281".

## Revisions

Every save, every draft by a model and every return to an older text is a revision, with who made it. Saving the same text again makes no revision. Going back never erases anything: it makes a new revision with the older text. If someone saved after you opened the text, your save is refused and your text stays on the screen, so nothing is lost without you knowing. A text keeps its last 500 revisions.

## Drafting with a model

Choose **Draft with a model**, pick a connection and a model, and say what to write. The brief of the project and the current text go to the model as material. You see the estimated cost first, and the draft waits on the **Approvals** page like any costly generation, under the ceilings you set. When it is approved, the draft is a new revision marked as drafted by a model, with the provider, the model and what it cost. Your earlier revisions are never touched. For a caption you can draft one network only.

What a model writes is untrusted text: an agent that reads it sees it inside a marked block, and the preview never turns it into markup.
