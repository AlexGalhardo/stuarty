## What you can do today

- Import media, cut and arrange it on a timeline, add text and captions, and export a verified MP4.
- Save a project as a template and start new projects from it.
- Let an agent do the same through the MCP server or the CLI.
- Read the planning documents in the [repository](https://github.com/AlexGalhardo/stuarty/tree/main/docs): requirements, architecture decisions and specifications.

## Install

The product runs only on your machine. Each [release](https://github.com/AlexGalhardo/stuarty/releases) attaches:

- installers of the local server, which install `stuarty` and a shortcut that starts the server and opens the editor in your browser; uninstalling removes the program and keeps your workspace:
  - Windows 11: `stuarty-<version>.exe`, with the dots of the version written as dashes (`stuarty-0-28-0.exe`)
  - Debian and Ubuntu: `stuarty_<version>_linux_<arch>.deb`
  - any Linux: `stuarty-<version>.AppImage` (`stuarty-0-28-0.AppImage`)
  - macOS: `stuarty_<version>_darwin_<arch>.pkg`
- archives for six targets and `checksums.txt`, signed with cosign.

The container image of the web version is started with a command of this shape, which publishes the port on your computer only (`latest` is for trying it out; pin `X.Y.Z` for a server you keep). Put a clip in `~/clips` first (an MP4 with sound is fine): the second `-v` and `STUARTY_IMPORT_ROOTS` let the server import from that folder, and the name lets you run the CLI inside the container below:

```bash
docker run -d --name stuarty -p 127.0.0.1:7878:7878 -v stuarty:/data \
  -v "$HOME/clips:/media:ro" -e STUARTY_IMPORT_ROOTS=/media \
  -e APP_KEY="$(openssl rand -base64 32)" \
  -e STUARTY_ADMIN_EMAIL=admin@example.com \
  -e STUARTY_ADMIN_PASSWORD="choose-a-long-password" \
  ghcr.io/alexgalhardo/stuarty:latest
```

The server listens on `127.0.0.1:7878` and is reachable from your computer only. Open that address in a browser and sign in with the email and password above (a container runs in network mode, so sign-in is required). Your projects and media stay in the `stuarty` volume, so a new container with the same volume finds them again. The [installation page](/docs/installation) has the details of the image and its tags.

### Your first export from the container

On Windows with Git Bash set `MSYS_NO_PATHCONV=1` so `/media` is not rewritten. Create an API key with the administrator above (the secret is shown once), then run the CLI inside the container with it. The server chooses the ids: use the ones each command prints.

```bash
APP=http://localhost:7878
curl -fsS -c jar.txt -H "Content-Type: application/json" -H "Origin: $APP" \
  -d '{"email": "admin@example.com", "password": "choose-a-long-password"}' "$APP/auth/login"
curl -fsS -b jar.txt -H "Content-Type: application/json" -H "Origin: $APP" \
  -d '{"name": "first-export", "scopes": ["read", "edit", "media", "render"]}' "$APP/api/v1/keys"

export STUARTY_KEY="vvk_<the secret from the last command>"
vv() { docker exec -i -e STUARTY_KEY stuarty stuarty "$@"; }
vv project:create --name "First export" --json                   # prints project_id
vv media:import /media/clip.mp4 --project <project id> --json    # prints asset_id
vv edit --project <project id> --ops - <<'EOF'
[{"op":"track.add","args":{"kind":"visual","name":"Video","id":"trk_f6g7h8j9k0"}},
 {"op":"clip.add","args":{"track_id":"trk_f6g7h8j9k0","asset_id":"<asset id>","start":"0s","duration":"2s","id":"itm_m1n2p3q4r5"}}]
EOF
vv export --project <project id>
```

The last command waits and prints `succeeded`; the MP4 is in `/data/exports/<project id>/<job id>.mp4` and `vv job:show <job id>` lists the checks it passed (copy it out with `docker cp`). [Run the Docker image](/docs/self-hosting/docker) has the details, and `scripts/first-export-timing.sh` in the repository runs these steps and times them. Stop the container with `docker rm -f stuarty`; the volume keeps your projects.

### Windows SmartScreen and macOS Gatekeeper

The installers are not signed with a paid code-signing certificate, so both systems warn before the first run.

- **Windows.** SmartScreen shows "Windows protected your PC" for the `.exe`. Choose "More info", then "Run anyway".
- **macOS.** Gatekeeper says the package cannot be opened because Apple cannot check it. Control-click the `.pkg` and choose Open, or allow it in System Settings, Privacy & Security.

To check a download before you run it, verify `checksums.txt` with cosign and compare the SHA-256 of the file, as described in the [security policy](https://github.com/AlexGalhardo/stuarty/blob/main/.github/SECURITY.md).

## For a person

1. Start the server (`stuarty serve`).
2. Run `stuarty open`. It finds the running server of the workspace, wherever it listens, and opens the editor signed in with a one-time code. The plain address answers 401 until a browser has signed in this way (in network mode, open it and sign in with your account).

## For an agent

Pick one of three routes to the same project:

1. The stdio MCP server: the command is `stuarty mcp`.
2. The CLI with `--json`, for example `stuarty project:create --name "Launch teaser" --json`.
3. The HTTP API of `stuarty serve`, with Streamable HTTP MCP at `POST /mcp`.

These routes share one set of operations, so an agent and a person see the same result. The [agents overview](/docs/agents/overview) shows how to connect one.
