## You will learn

- which of the three ways to install fits you;
- why Windows and macOS warn before the first run, and how to check a download.

## The idea

Stuarty runs only on a computer you own. You install one program, `stuarty`. It serves the editor in your browser, the MCP server, the CLI and the HTTP API from the same process and the same workspace.

| You want | Install | Page |
| --- | --- | --- |
| to try it on your Windows computer, in a window | the desktop application | [Install on Windows](/docs/install-windows) |
| a command line, agents and scripts on your computer | the local server | [Install on Windows](/docs/install-windows) |
| the same thing on any system with Docker | the container image | [Install with Docker](/docs/install-docker) |
| it always on, for you or a small team, with HTTPS | the server package | [Install on a server](/docs/install-server) |

Each release attaches installers (Windows 11, a macOS package, `.deb`, `.AppImage`), archives for six targets and `checksums.txt`, signed with cosign.

## The installers are not signed with a paid certificate

There is no Apple Developer ID, no notarization and no Windows code-signing certificate. Windows and macOS therefore warn before the first run. This is expected; what proves the file is genuine is the checksum and the signature in the release, which you can [verify](/docs/self-hosting/verify-a-release).

- **Windows.** SmartScreen shows "Windows protected your PC". Choose **More info**, then **Run anyway**.
- **macOS.** Gatekeeper says the app cannot be opened because Apple cannot check it. Control-click (right-click) the app, choose **Open**, then **Open** again.
- **Debian and Ubuntu.** No warning. Install with `sudo apt install ./stuarty-desktop_X.Y.Z_linux_amd64.deb`.

## From install to a first export

Import and export need FFmpeg. The container image carries one. The installers published so far do not: install FFmpeg yourself ([Install on Windows](/docs/install-windows)). The Windows desktop installer is built to carry its own LGPL FFmpeg, and it will from the first release that pins it; see [FFmpeg, codecs and licences](/docs/self-hosting/ffmpeg-and-licences).

To time the path from a clean workspace on your own machine, run `scripts/first-export-timing.sh --binary <path to stuarty>`. It starts the server, creates a project, imports a clip, places it and exports and verifies the MP4. The same script times the container: `bash scripts/first-export-timing.sh [image]`. Downloading the installer or the image is not part of the time, because it depends on your connection. This page gives no figure: a measurement of an older build says nothing about yours.

## Common mistakes

- FFmpeg is not found. The editor uses your FFmpeg for the binary installers, and `STUARTY_FFMPEG` and `STUARTY_FFPROBE` name the binaries explicitly. See the [configuration variables](/docs/reference/configuration).
- Opening the plain address in a browser and getting 401. A local server answers 401 until a browser has signed in with `stuarty open`.
