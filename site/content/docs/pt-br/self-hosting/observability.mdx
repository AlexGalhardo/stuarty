## O que você vai aprender

- onde estão os logs e como eles rotacionam;
- para que servem a tabela de auditoria e a tabela de tarefas;
- como ligar o OpenTelemetry.

## A ideia

O servidor grava **logs estruturados** no erro padrão e em um arquivo rotativo, `<workspace>/logs/vukem-video.log`. O arquivo rotaciona a 10 MiB e mantém os três arquivos antigos mais novos como `vukem-video.log.1` a `.3`. Uma linha traz o identificador da requisição ou da tarefa, o ator e o projeto. Nomes de arquivos de mídia e texto de transcrições não são registrados acima do nível de depuração, e nenhum segredo é: a senha do primeiro administrador e toda chave de API ficam fora do log. Em um contêiner, `docker logs vukem-video` mostra o erro padrão.

Três registros respondem a perguntas diferentes, e nenhum é copiado para os outros:

| Registro | Responde | Leia com |
| --- | --- | --- |
| Logs | o que o servidor fez e o que deu errado | `docker logs`, ou o arquivo em `logs/` |
| A tabela de auditoria | quem mudou o quê, em qual projeto | `vukem-video audit` |
| A tabela de tarefas | trabalho longo: exportações e transcrições | `vukem-video job:list` |

O produto não envia telemetria e não tem análises nem relatório de falhas. A observabilidade é sua para ligar.

## OpenTelemetry

Defina `OTEL_EXPORTER_OTLP_ENDPOINT` como o seu próprio coletor e o servidor envia traces e métricas para lá. Sem a variável, nenhum exportador é criado e nenhuma conexão é feita. O coletor vê tempos de requisição e identificadores, não a sua mídia.

```bash
# add this option to the docker run command of the Docker page
-e OTEL_EXPORTER_OTLP_ENDPOINT=http://collector.example.com:4318
```

## Início rápido

```bash
vukem-video doctor --full
vukem-video audit --limit 20
curl -fsS http://localhost:7878/up
```

O `doctor --full` verifica a instalação e o espaço de trabalho (veja [o pacote de diagnóstico](/docs/troubleshooting/diagnostic-bundle)). O `GET /up` é a rota de saúde que a imagem usa.

## Erros comuns

- Procurar logs no navegador. O editor mostra um aviso e um estado de conexão; os detalhes estão no log do servidor.
- Apontar o endpoint para um serviço que não é seu. Ele recebe os traces de toda requisição.
- Esperar que o log cresça sem limite. Ele não cresce: no máximo três arquivos antigos.
