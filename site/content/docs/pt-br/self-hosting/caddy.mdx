## O que você vai aprender

- como dar ao Vukem Video um endereço `https` público com o Caddy;
- as três configurações de que o servidor precisa para confiar no proxy;
- como conferir.

## A ideia

O modo de rede exige TLS. Você pode dar ao servidor um certificado diretamente (`TLS_CERT_FILE` e `TLS_KEY_FILE`), ou colocar um proxy reverso na frente. O proxy recomendado é o [Caddy](https://caddyserver.com/): ele obtém e renova certificados sozinho. O produto documenta apenas o Caddy.

O servidor aceita uma requisição como `https` apenas quando ela vem de um endereço em `TRUSTED_PROXIES`, `TRUST_FORWARDED_PROTO` é `true` e o proxy enviou `X-Forwarded-Proto: https`. Uma requisição que afirma `http` por esse cabeçalho é recusada, quem quer que a envie.

## Início rápido

Um `Caddyfile` para um servidor na mesma máquina do Vukem Video:

```text
video.example.com {
	reverse_proxy 127.0.0.1:7878
}
```

O Caddy envia `X-Forwarded-Proto` e o endereço do cliente sozinho. Inicie o Vukem Video com:

```bash
export VUKEM_VIDEO_MODE=network
export VUKEM_VIDEO_ADDR=127.0.0.1:7878
export APP_URL=https://video.example.com
export APP_KEY="$(cat /etc/vukem-video/app-key)"
export TRUSTED_PROXIES=127.0.0.1
export TRUST_FORWARDED_PROTO=true
vukem-video serve
```

- `APP_URL` é o endereço que as pessoas digitam. O `Host` e o `Origin` de cada requisição precisam ser iguais a ele.
- `TRUSTED_PROXIES` lista os endereços ou intervalos do proxy, como o servidor os vê. Se o Caddy roda em outro contêiner, informe o intervalo dessa rede, como `172.18.0.0/16`.
- Com o proxy na mesma máquina, vincule o servidor ao loopback para que apenas o Caddy o alcance. Em um contêiner, publique `127.0.0.1:7878:7878` e defina `APP_URL` como o endereço público.

Confira o endereço, depois a rota de saúde:

```bash
curl -fsS https://video.example.com/up
```

## Erros comuns

- Esquecer o `TRUSTED_PROXIES`: todos os clientes passam a compartilhar um único endereço de limite de taxa, e o servidor registra um aviso. Atrás de um proxy, o limite de logins com falha bloquearia todo mundo de uma vez.
- Um `APP_URL` com `http` e um nome público: recusado na inicialização. A exceção do HTTP simples é apenas `localhost` ou `127.0.0.1`.
- Deixar o proxy reescrever o cabeçalho `Host`. Mantenha o padrão, que encaminha o host original.
- Usar outro servidor web. Apenas o Caddy é documentado e testado.
