## O que você vai aprender

- como iniciar uma exportação e acompanhá-la;
- o que precisa ser verdade antes de uma exportação ser aceita.

## A ideia

Uma exportação é uma **tarefa**. Ela renderiza a revisão atual, codifica um MP4 com o FFmpeg e verifica o arquivo (streams, duração, dimensões, formato de pixel e faststart) antes de marcar a tarefa como `succeeded`. Um arquivo que falha na verificação nunca é informado como pronto.

A exportação é recusada enquanto a verificação encontrar um erro, com `E_LINT_BLOCKING` e os primeiros achados. Avisos nunca bloqueiam.

## Início rápido

<Tabs>
<Tab title="CLI">

```bash
vukem-video lint --project prj_7k2m9x4q1b
vukem-video export --project prj_7k2m9x4q1b
```

A CLI espera pela tarefa. Use `--no-wait` para voltar na hora e `vukem-video job:show <job id> --wait` depois.

</Tab>
<Tab title="MCP">

`job_start` com `{"project_id": "prj_7k2m9x4q1b", "kind": "export", "wait_ms": 25000}`, depois `job_get` com `wait_ms` até o estado ser final.

</Tab>
</Tabs>

O resultado de uma exportação concluída traz o caminho do arquivo em `<workspace>/exports/<project id>/<job id>.<extension>`, o seu tamanho e a sua duração.

## Formatos

Uma exportação é um MP4, a menos que você escolha outro formato com `--format` (CLI) ou `args.format` (MCP e API HTTP).

| Formato | Arquivo | O que é |
| --- | --- | --- |
| `mp4` | `.mp4` | vídeo H.264 e áudio AAC (o padrão); precisa de um codificador H.264 |
| `gif` | `.gif` | os quadros compostos, sem áudio; não precisa de codificador |
| `wav` | `.wav` | a mixagem de áudio em PCM de 16 bits, 48 kHz, estéreo |
| `aac` | `.m4a` | a mesma mixagem em AAC dentro de um contêiner MP4 |

```bash
vukem-video export --project prj_7k2m9x4q1b --format gif
```

Com MCP: `job_start` com `{"project_id": "prj_7k2m9x4q1b", "kind": "export", "args": {"format": "wav"}}`.

## Troque uma linha do tempo com o OpenTimelineIO

O `otio:export` grava a linha do tempo de um projeto como um arquivo [OpenTimelineIO](https://opentimelineio.org), para abri-lo em outro editor. Ele grava o arquivo na máquina que executa o comando, na pasta atual como `<project name>.otio`, ou onde `--out` indicar; ele se recusa a substituir um arquivo, a menos que você acrescente `--force`. O comando lista o que o formato não consegue carregar (por exemplo, efeitos), para que nada se perca em silêncio.

```bash
vukem-video otio:export --project prj_7k2m9x4q1b --out cut.otio
vukem-video otio:import cut.otio --project prj_7k2m9x4q1b --dry-run
vukem-video otio:import cut.otio --project prj_7k2m9x4q1b --base-revision 12
```

O `otio:import` lê um arquivo da máquina que roda o servidor e o aplica ao projeto como um único lote, então um `undo` o reverte. A taxa de quadros do arquivo precisa ser a do projeto. A mídia do arquivo nunca é aberta: uma referência é associada pelo nome a uma mídia que já está no projeto, e as que não correspondem a nada são listadas como não resolvidas. O `--dry-run` mostra o que mudaria; o `--base-revision` assume a revisão atual por padrão. A API HTTP tem `GET` e `POST /api/v1/projects/{id}/otio`. Não há ferramenta MCP para o OpenTimelineIO.

## Exporte um pacote de projeto

Um pacote é um único arquivo, `<name>.vvbundle`, que guarda um projeto e tudo de que ele precisa, para fazer uma cópia de segurança ou entregá-lo a outra pessoa. É um zip com o documento do projeto, a mídia original, as fontes que o projeto usa e, a menos que você a deixe de fora, o registro de operações com o histórico de edições. Proxies, miniaturas e transcrições não são incluídos; eles são gerados de novo quando o pacote é aberto.

```bash
vukem-video bundle:export --project prj_7k2m9x4q1b --wait
vukem-video bundle:export --project prj_7k2m9x4q1b --no-log --wait
```

Como uma exportação, um pacote é uma tarefa: o `--wait` a acompanha, e o arquivo é gravado em `<workspace>/exports/<project id>/` como `bundle-r<revision>-<job id>.vvbundle`. O `--no-log` deixa o histórico de fora, o que esconde quem editou e por quê. Um projeto na lixeira não pode ser exportado. O comando roda na máquina que possui o espaço de trabalho.

## Importe um pacote de projeto

O `bundle:import` cria um projeto a partir de um arquivo `.vvbundle`. Ele lê o arquivo na máquina que roda o servidor, confere-o antes de mudar qualquer coisa e copia para o espaço de trabalho a mídia e as fontes que ele traz. O projeto abre na hora; suas mídias aparecem como em ingestão enquanto os proxies, as miniaturas e as transcrições são gerados de novo.

```bash
vukem-video bundle:import launch-teaser.vvbundle
vukem-video bundle:import launch-teaser.vvbundle --as-new
vukem-video bundle:import launch-teaser.vvbundle --dry-run
```

Sem `--as-new`, o projeto mantém o seu id e o seu histórico de edições. Se já existe um projeto com esse id, mesmo na lixeira, a importação é recusada com `E_ID_EXISTS`. Com `--as-new`, o projeto recebe um id novo e começa na revisão 1 sem histórico, porque o histórico de outro projeto não pertence a um projeto novo. Um servidor com contas exige `--as-new`. O `--dry-run` confere o arquivo e informa o que seria criado. Um arquivo danificado, grande demais, de formato diferente ou vindo de uma versão mais nova do produto é recusado com `E_VALIDATION` e um motivo, e nada é importado. A API HTTP tem a mesma operação como `POST /api/v1/projects/import`.

Não há ferramenta MCP para pacotes e o editor ainda não tem uma entrada para pacotes.

## Erros comuns

- Nenhum codificador H.264 funciona nesta máquina: `E_NO_ENCODER`. `gif`, `wav` e `aac` ainda são exportados.
- Importar um pacote cujo id de projeto já existe: `E_ID_EXISTS`. Use `--as-new`.
- Exportações demais ao mesmo tempo: `E_QUEUE_FULL`, que pode ser repetido. `VUKEM_VIDEO_MAX_EXPORTS` define o limite.
