## O que você vai aprender

- o que são um modelo, um espaço e uma cor de modelo;
- quais modelos iniciais todo espaço de trabalho tem;
- como criar um projeto a partir de um modelo e como salvar um.

## A ideia

Um **modelo** é um projeto com **espaços** nomeados. Um espaço marca um item que você preenche ao iniciar um novo projeto: um espaço de **mídia** recebe uma mídia, um espaço de **texto** recebe uma string e um espaço de **legenda** recebe palavras. Um espaço de mídia tem uma política de duração: `fit` mantém a duração do espaço e exige uma mídia longa o bastante, `stretch_timeline` pega o resto da mídia e move os itens seguintes. Um espaço pode ser `required` (o padrão) ou opcional.

Um modelo também pode guardar cores nomeadas. Um estilo, uma forma ou o fundo se refere a uma delas como `$name`, então uma única mudança recolore o modelo inteiro (`template.set_info`). Um projeto pode tomar essas cores do seu kit de marca: veja [Fontes e o kit de marca](/docs/guide/brand-kit).

Todo espaço de trabalho começa com três **modelos iniciais**, que existem desde a primeira inicialização e são compartilhados com todos os usuários no modo de rede:

| Modelo | Formato | Espaços |
| --- | --- | --- |
| [Corte vertical com legendas](/docs/guide/template-vertical-cut) | 1080 x 1920 | `clip`, `subtitles` |
| [Teaser de produto](/docs/guide/template-product-teaser) | 1920 x 1080, 10 s | `shot_1`, `shot_2`, `music`, `headline`, `call_to_action` |
| [Cartão de citação](/docs/guide/template-quote-card) | 1080 x 1080 | `quote`, `author` |

Criar um projeto a partir de um modelo funciona mesmo quando um espaço obrigatório está vazio. O resultado lista os espaços `unfilled`, e a verificação (lint) informa `L_SLOT_UNFILLED` até você preenchê-los.

O editor ainda não tem um seletor de modelos nem um formulário de espaços. Use a CLI, a ferramenta `template` do MCP ou um agente; os espaços também são editados com a paleta de comandos (`Ctrl+K`).

## Início rápido

<Tabs>
<Tab title="CLI">

```bash
vukem-video template:list
echo '{"headline": {"text": "Spring sale"}, "shot_1": {"asset_id": "ast_4h6j8k2m3n"}}' > fill.json
vukem-video template:new tpl_5n8b2v6c1x --name "Spring sale" --fill fill.json
vukem-video template:save --project prj_7k2m9x4q1b --name "My intro" --description "Logo and title"
```

Com um kit de marca, acrescente `--brand-color accent` (uma cor do modelo) e `--brand-font "Brand Sans"` (uma família do kit) ao `template:new`.

</Tab>
<Tab title="MCP">

`template` com `{"action": "list"}`, depois `{"action": "new", "template_id": "tpl_5n8b2v6c1x", "name": "Spring sale", "fill": {"headline": {"text": "Spring sale"}}}`. As outras ações são `save`, `export` e `import`.

</Tab>
</Tabs>

Para transformar o seu próprio projeto em um modelo, marque itens com `slot.mark` (o `name` são letras minúsculas, dígitos e sublinhados, até 40 caracteres), depois `template:save`. Preencha um espaço de um projeto aberto com `slot.fill` e remova uma marca com `slot.unmark`. O `template:export` grava um arquivo que o espaço de trabalho guarda e o `template:import` adiciona um arquivo desses à biblioteca. O arquivo carrega as fontes de usuário que o modelo usa, então um modelo feito com as suas próprias fontes funciona em outra máquina; veja [Fontes e o kit de marca](/docs/guide/brand-kit). Para mover um projeto inteiro, com a sua mídia, use um [pacote](/docs/guide/exporting).

## Erros comuns

- Preencher um espaço com mais de um entre `asset_id`, `text` e `words`: exatamente um é permitido.
- Preencher um espaço `fit` com uma mídia mais curta que o espaço: `E_SLOT`.
- Esquecer que um modelo é uma cópia: mudar o projeto feito a partir dele nunca muda o modelo.
