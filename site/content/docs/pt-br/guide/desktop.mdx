## O que você vai aprender

- o que é o aplicativo de desktop e o que ele acrescenta ao `vukem-video serve`;
- como compilá-lo e iniciá-lo no Windows;
- o que fazem o menu, o seletor de arquivos e a tela cheia.

## A ideia

O aplicativo de desktop é uma pequena casca em volta do mesmo programa. Ele inicia o `vukem-video serve` em uma porta livre de `127.0.0.1`, espera até o servidor subir e abre o editor em uma janela nativa. Ele não tem lógica de edição própria: a janela mostra o mesmo editor que você tem no navegador, sobre o mesmo [espaço de trabalho](/docs/workspace), e nenhum login é necessário porque o servidor roda em modo local na sua máquina.

Fechar a janela, escolher Sair ou uma falha da casca para o servidor que ela iniciou. A janela não consegue sair do próprio servidor: se uma página termina em outro endereço, a casca devolve a janela ao editor.

## Início rápido

Você precisa do Go, do Bun e, no Windows 11, de mais nada (o WebView2 vem com o sistema). A partir da raiz do repositório:

```bash
cd web && bun install --frozen-lockfile && bun run build && cd ..
go build -o dist/vukem-video.exe ./web/cmd/app
cd desktop/shell/app && go build -ldflags "-H windowsgui" -o ../../../dist/vukem-video-desktop.exe .
```

Coloque os dois arquivos em uma pasta e dê um duplo clique em `vukem-video-desktop.exe`. Para usar um programa servidor em outro lugar, inicie-o como `vukem-video-desktop -binary <path to vukem-video>`. A primeira inicialização pode levar dezenas de segundos enquanto o componente de janela sobe; as seguintes são mais rápidas.

O espaço de trabalho é `~/.vukem-video`, ou a pasta em `VUKEM_VIDEO_HOME` se você a definir antes de iniciar o aplicativo. Você ainda pode executar o mesmo servidor com `vukem-video serve` e abri-lo em um navegador; os dois são os mesmos dados.

## O menu, o seletor de arquivos e a tela cheia

| Menu | Entrada | O que faz |
| --- | --- | --- |
| File | Open workspace folder | abre a pasta do espaço de trabalho no gerenciador de arquivos |
| File | Quit | para o servidor e fecha a janela |
| View | Reload | recarrega o editor |
| View | Toggle full screen | liga e desliga a tela cheia; a tecla é `F11` |
| Help | About | mostra a versão |

No navegador, você cola um caminho de arquivo para importar mídia. Na janela de desktop, o editor mostra **Choose files**, que abre o diálogo de arquivos nativo e importa os arquivos escolhidos. Soltar arquivos sobre a janela os importa do mesmo modo. O editor envia apenas os caminhos ao servidor, que copia os arquivos para o espaço de trabalho, então nada é enviado para lugar nenhum.

## Atualizações

O aplicativo pode procurar uma versão mais nova, e só quando você pede. A configuração **Check for updates at start-up** vem desligada; desligada, o aplicativo não abre nenhuma conexão. **Help**, **Check for updates** faz uma verificação para aquela ação. Uma verificação é uma requisição HTTPS de um arquivo assinado, `feed.json`, no site do projeto no GitHub Pages; o instalador oferecido é baixado do mesmo endereço, e o aplicativo confere o SHA-256 e a assinatura dele antes de executá-lo. Um arquivo que não bate é recusado e o aplicativo continua em execução. No Windows o instalador é iniciado para você e o aplicativo fecha; no macOS e no Linux o aplicativo mostra a página da versão. Uma compilação feita sem a chave de assinatura embutida (por exemplo, uma que você mesmo compilou) não tem verificação de atualização e diz isso no menu. Como o feed é assinado está na página [Verifique uma versão](/docs/self-hosting/verify-a-release).

## Erros comuns

- A compilação não é assinada com um certificado pago, então o Windows SmartScreen avisa antes da primeira execução. Veja a [Instalação](/docs/installation) para as etapas no Windows e no macOS.
- Toda página responde com um erro: o front-end não foi compilado. Execute `bun run build` em `web/` antes do `go build`.
- Uma segunda cópia do programa no mesmo espaço de trabalho: o espaço de trabalho fica bloqueado e a segunda não consegue iniciar. Veja [o espaço de trabalho está bloqueado](/docs/troubleshooting/workspace-locked).
- Procurar compilações para macOS ou Linux: elas não são verificadas, então nada aqui é prometido para elas.
