## O que você vai aprender

- onde uma exportação gasta o seu tempo;
- o que verificar e o que mudar;
- o que é medido e o que não é.

## A ideia

Uma exportação tem quatro etapas: ela planeja os quadros, compõe cada quadro em Go, entrega os quadros ao FFmpeg e verifica o arquivo. Medido no benchmark do próprio projeto, o limite é **compor os quadros** (o FFmpeg decodificando as origens e convertendo-as para RGBA), e o codificador quase não importa. Um codificador de hardware, portanto, encurta apenas uma pequena parte do tempo. O tempo cresce com o número de quadros, o tamanho do quadro e o número de camadas com efeitos na tela.

Os números de uma tabela do repositório, `docs/perf/`, são os de uma máquina em um commit, e uma máquina ocupada mede várias vezes mais lento que uma ociosa. Meça a sua própria máquina antes de decidir que algo está errado.

## Início rápido

1. Verifique o que mais a máquina está fazendo. As exportações dividem a CPU com ingestões, transcrições e os seus outros programas.
2. Leia a tarefa, que informa o codificador usado e a duração:

```bash
vukem-video job:list --project prj_7k2m9x4q1b --state all
vukem-video job:show job_4h8k2m6p9t
vukem-video doctor --full
```

3. Exporte um trecho curto para comparar: `vukem-video export --project prj_7k2m9x4q1b --start 0s --end 5s`.

| Verificação | O que fazer |
| --- | --- |
| O codificador é `libopenh264` e existe um de hardware | o `doctor --full` mostra por que o de hardware falhou; corrija o driver, ou force um com `VUKEM_VIDEO_ENCODER`. O ganho é pequeno |
| O projeto é maior do que a saída precisa | defina o tamanho do quadro para o que a plataforma mostra; 1080 x 1920 é o tamanho vertical usual |
| As origens são muito grandes ou de um codec pesado | a importação gera um proxy para o editor, mas a exportação lê o original: recodifique uma origem menor |
| Várias exportações estão na fila | `VUKEM_VIDEO_MAX_EXPORTS` é 2 por espaço de trabalho e 1 por usuário ou chave; as demais esperam |
| O disco está quase cheio ou lento | o espaço de trabalho e o `tmp/` ficam em um volume; libere espaço e use um disco rápido |
| Um contêiner com um limite pequeno de CPU | dê a ele mais CPUs |

## Erros comuns

- Mudar o codificador para acelerar uma exportação que é limitada pela composição.
- Iniciar uma exportação enquanto uma transcrição longa roda em uma máquina pequena.
- Cancelar e reiniciar uma exportação longa: o trabalho se perde. Use `job:show --wait` para acompanhá-la.
