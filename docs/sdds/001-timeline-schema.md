- Owner area: senior-a (command core and schema)

## 1. Purpose

This document defines the JSON document that represents one timeline. Since ADR-0039 a project is a production that holds timelines (SDD-005 section 5.12), and in this document "project" still means the timeline document: its name, its `prj_` identifier and its fields do not change. The document is the single thing every command changes, the frame plan reads and the database stores. It is detailed enough to write `core/timeline` (Go types, validation, canonical encoding, migrations) and its generated JSON Schema without further questions.

Out of this document: how commands change the document (SDD-002), how it becomes pixels (SDD-004), how it is stored (SDD-005).

## 2. Conventions

1. **Time.** Every time quantity is a non-negative integer number of frames at the project frame rate (ADR-0004). Field names carry no unit suffix; this rule is the unit. There is no floating-point time in the document.
2. **Space.** Positions and sizes are in pixels of the project frame, as JSON numbers. The origin is the top-left corner; x grows right, y grows down. An item's position is the position of its centre.
3. **Fractions.** Opacity, crop and volume are JSON numbers. Opacity and crop are between 0 and 1.
4. **Rationals.** A rational is an object `{"num": int, "den": int}` with both positive.
5. **Colours.** Strings `#RRGGBB` or `#RRGGBBAA`, upper or lower case accepted, stored upper case.
6. **Identifiers.** A string `<prefix>_<10 characters>` where the characters are lower-case Crockford base32 (`0-9`, `a-z` without `i`, `l`, `o`, `u`). Prefixes: `prj` project, `ast` asset, `trk` track, `itm` item. Keyframes and caption words have no identifier: a keyframe is addressed by its item, property and frame, a word by its item and index. Identifiers are generated by the caller of the core from a cryptographic random source and supplied to `apply`; no command generates one. `core/timeline` offers `NewID(prefix)` and `ValidID(prefix, id)` for those callers.
7. **Maps.** Collections are JSON objects keyed by identifier. The key equals the object's `id`.
8. **Canonical encoding.** The stored form is JSON with object keys sorted, no insignificant whitespace, numbers in the shortest form that round-trips, and fields equal to their default omitted. Two exceptions: a style object (`style` of a text or caption item, `caption_style` of a track) stores exactly the keys that were set, whatever their values, because they take part in a cascade (section 3.7); and `x` and `y`, whose default depends on the frame size, are stored once they were set, absent meaning centred. Two documents are equal when their canonical encodings are equal byte for byte. `core/timeline` provides `Canonical(doc) []byte`. A style object or a crop that has no key set is omitted, since it means the same as none. A number that is not finite, which `Validate` rejects as `V_SHAPE`, is written as `null`.
9. **Unknown fields.** A field the binary does not know is preserved on decode and written back on encode, at every object level. This keeps a document written by a newer minor version intact when an older binary edits it.

## 3. Document

```json
{
  "schema_version": 1,
  "id": "prj_7k2m9x4q1b",
  "name": "Launch teaser",
  "settings": { },
  "assets": { },
  "tracks": { },
  "items": { },
  "fonts": { }
}
```

| `id` | project id | yes | |
| `name` | string, 1 to 120 characters | yes | |

### 3.1 Settings

| Field | Type | Default | Constraint |
| --- | --- | --- | --- |
| `width` | integer | 1080 | even, 16 to 4096 |
| `height` | integer | 1920 | even, 16 to 4096 |

### 3.2 Asset

An asset is a reference to a file in the content store plus the facts the frame plan needs, copied from the ingest probe so that planning is a pure function of the document.

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `id` | asset id | yes | |
| `hash` | string | yes | `sha256:` followed by 64 hex characters; identity of the original file |
| `kind` | `"video"`, `"audio"`, `"image"`, `"lut"` | yes | `lut` (added by TASK-0254) is a colour lookup table, a `.cube` file: it has no picture facts, is never placed on a track and is used only through the `lut` of a clip (section 3.5). A `clip` or `audio` item, or a slot, that names a `lut` asset is `V_ASSET_REF` |
| `name` | string | yes | original file name; display only; untrusted text |
| `frame_rate` | rational | video only | frame rate of the normalized media |
| `frame_count` | integer | video only | number of frames of the normalized media |
| `sample_count` | integer | when it has audio | samples at 48,000 Hz of the normalized audio |
| `width`, `height` | integer | video and image | pixels after the display matrix was applied |
| `has_audio` | boolean | video only | default false |
| `has_alpha` | boolean | video and image | default false. True when the normalized video keeps an alpha channel (SDD-011 4.3.5), or when a still image has one (a PNG logo, SDD-011 4.7); the export then composes the clip over the layers below instead of drawing it opaque |
| `frame_delays` | array of integers, 2 to 1,000 | animated image only | Display time of each frame in milliseconds, 10 to 60,000 each, read from the file by ingest. Present only on an `image` asset, with `frame_count` equal to its length; its presence is what makes the image animated (`Asset.IsAnimated`). A still image has neither |

An asset appears in the document only after its ingest produced the normalized media (ADR-0010); for a `lut` asset, after the `.cube` file was read and checked.

**Animated image (RF-028).** An animated GIF, WebP or APNG is an `image` asset with `frame_count` and `frame_delays`; there is no fourth asset kind, so every rule that treats an image (no duration limit, `speed` and `source_in` ignored, `fit`, `crop`) holds unchanged and a binary that does not know the fields keeps them. The animation plays from its first frame at the start of the item, loops for as long as the item lasts, and is shown frame by frame by the cumulative delays (the frame at item time `t` is chosen in SDD-004 §3.3 by `t` in milliseconds, rounded to the nearest, modulo the sum of the delays; there is no hold-at-the-last-frame mode). A sticker is an image or animated image on a visual track above the picture, not a type. `frame_delays` on a video or audio asset is `V_SHAPE`. Adding the fields does not change `schema_version` (section 6, rule 2).

**Asset duration in project frames** is derived, never stored: for video, `floor(frame_count * fps.num * frame_rate.den / (fps.den * frame_rate.num))`; for audio, `floor(sample_count * fps.num / (48000 * fps.den))`; an image has no duration limit.

#### 3.3.1 Track order

`order` is a non-empty string of characters from `0-9a-z`. Tracks are ordered by comparing `order` as byte strings, ascending. **The first track in that order is the top layer**: it is drawn last, over the others. Audio tracks follow the same ordering for display only. No two tracks have the same `order`. A new position between two tracks is a string that sorts between theirs; `core/timeline` provides `OrderBetween(a, b string) string` implementing the standard fractional indexing algorithm over that alphabet, with `""` meaning "before the first" or "after the last". The algorithm is fixed, so that every implementation and every golden file produce the same strings. Read a string as the digits of a base-36 fraction (`0` to `9`, then `a` to `z`), a missing digit of `a` being 0 and an empty `b` being 1. Walk the positions from the left: when the digits of `a` and `b` are equal, copy the digit and continue; when they differ by more than one, append the digit halfway between them (rounded down) and stop; when they differ by exactly one, append the digit of `a` and from then on, for each further position, take the next digit `d` of `a` (0 when `a` is exhausted): if `d` is below 35 append the digit halfway between `d` and 36 (rounded down) and stop, otherwise append `z` and continue. Examples: `OrderBetween("", "")` is `"i"`; `OrderBetween("i", "")` is `"r"`; `OrderBetween("", "i")` is `"9"`; `OrderBetween("a0", "a1")` is `"a0i"`. A result never ends in `0`, so there is always room before it.

`blur`, `filter`, `filter_amount`, `chroma_key`, `blend`, `flip_x`, `flip_y`, `mask` and `effects` apply to every visual item (`clip`, `text`, `caption`, `shape`); on an `audio` item a non-default value is `V_SHAPE`. The order is: chroma key (SDD-004 §3.7), colour adjustment of section 3.5, then the filter, then blur, then the effects (SDD-004 §3.13), then opacity; the mask (SDD-004 §3.9) is applied after the blur and before the opacity, and the blend mode (SDD-004 §3.8) is how the result is then drawn over the layers below. The exact formulas and the plan fields are in SDD-004 §3.6.

### 3.5 Clip and audio items

A `clip` shows a video or image asset. An `audio` item plays an audio asset, or the audio of a video asset.

| `brightness` | number, -1 to 1 | 0 | clip | Keyframeable since TASK-0254 (NEW-15), like `contrast`, `saturation`, `temperature`, `tint` and `hue`: the property name is a key of `keyframes` and the range is that of the static value |
| `contrast` | number, 0 to 2 | 1 | clip | |
| `saturation` | number, 0 to 2 | 1 | clip | |
| `temperature` | number, -1 to 1 | 0 | clip | Added by TASK-0233. White balance on the warm-cool axis: positive raises red and lowers blue. Not keyframeable |
| `tint` | number, -1 to 1 | 0 | clip | White balance on the green-magenta axis: positive lowers green. Not keyframeable |
| `hue` | number, -180 to 180 | 0 | clip | Rotation of the colours about the grey axis, in degrees. Not keyframeable |
| `lut` | object or absent | absent | clip | Added by TASK-0254. `{asset, intensity}`: `asset` is the id of a `lut` asset of the project (otherwise `V_ASSET_REF`) and `intensity`, 0 to 1, how much of the table is mixed in (0 is the original picture, 1 the full table). The table is applied after the colour adjustments of this section. The core stores and checks the reference; reading the `.cube` file and applying it is the engine's (SDD-004 section 3.6). The commands store an intensity of 0 as absent. An `asset.remove` of the table is `E_IN_USE` while a clip uses it. Not keyframeable |

**Source range.** At timeline frame `t` inside the item, the asset position in project frames is `source_in + floor((t - start) * speed.num / speed.den)`. With a `speed_curve` the term `floor((t - start) * speed.num / speed.den)` is `Offset(t - start)` of SDD-004 §3.11, and the number of source frames the item reads is `ceil(duration * speed.num / speed.den)` with `speed` the mean, so the rule below is unchanged. With `reverse` the item shows the same source range backwards: the offset is `ceil(duration * speed.num / speed.den) - 1 - offset` (SDD-004 §3.12), so the range is again `source_in` to `source_in + ceil(...)`. The item must stay inside the asset: `source_in + ceil(duration * speed.num / speed.den)` is at most the asset duration in project frames. Images are exempt.

**Fit.** With `cover` the cropped asset is scaled uniformly until it covers the whole frame; with `contain`, until it fits inside it; with `none` it keeps its pixel size. `scale`, `x`, `y` and `rotation` apply after that.

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `shape` | `"rect"`, `"rounded_rect"`, `"ellipse"` | required | |
| `width`, `height` | number, greater than 0 | required | pixels before `scale` |
| `radius` | number | 0 | corner radius for `rounded_rect` |
| `fill` | colour | `#FFFFFF` | |
| `stroke_color` | colour | `#000000` | |
| `stroke_width` | number | 0 | |

### 3.7 Caption items

A `caption` is timed text burned into the picture, with per-word timing.

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `words` | array of Word, 1 to 60 | required | |
| `breaks` | array of integers | `[]` | indexes of words before which a line break is forced; without it lines wrap at the style's `max_width` |
| `linked_item` | item id | none | the clip whose speech this caption transcribes; lets retiming commands recompute it. May point to an item that no longer exists; that is not an error |
| `style` | CaptionStyle | none | overrides fields of the track's `caption_style` for this item |

Word:

| Field | Type | Meaning |
| --- | --- | --- |
| `text` | string, 1 to 80 characters | the word with its attached punctuation; untrusted text when it came from transcription |
| `start` | integer | first frame of the word, relative to the item's `start` |
| `duration` | integer, at least 1 | |

Words are in order, do not overlap, and end at or before the item's `duration`.

CaptionStyle has every field of TextStyle (with `size` defaulting to 64 and `max_width` to 0.8 × frame width) plus:

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `position` | `"bottom"`, `"middle"`, `"top"`, `"custom"` | `"bottom"` | vertical anchor inside the safe area, not the frame: in a 9:16 frame the safe area ends at 65% of the height (y 1248 of 1920), so `bottom` puts the caption's lower edge there; for a caption lower than that use `custom` with `y` (SDD-004 section 4.1); `custom` uses the item's `x`, `y` |
| `highlight` | `"none"`, `"word"` | `"none"` | `word` draws the word being spoken in the highlight colours. Any other value is `E_VALIDATION` (SDD-002 §A.10) |
| `highlight_color` | colour | `#FFE600` | text colour of the highlighted word |
| `highlight_background` | colour | none | box behind the highlighted word |

The effective style of a caption item is the defaults, overridden by the track's `caption_style`, overridden by the item's `style`.

### 3.8 Transitions and keyframes

Transition:

| Field | Type | Meaning |
| --- | --- | --- |
| `kind` | `"fade"`, `"slide_left"`, `"slide_right"`, `"slide_up"`, `"slide_down"`, `"zoom"`, `"whip"`, `"dip"`, `"wipe"`, `"spin"`, `"shrink"`, `"grow"` | for `transition_in` the item arrives from that side; for `transition_out` it leaves towards it. `zoom`, `whip`, `dip` and `wipe` were added by TASK-0278 |
| `duration` | integer, at least 1 | frames |
| `color` | `#RRGGBB` or `#RRGGBBAA` (a template colour reference is allowed) | `dip` only: the colour the item dips to; absent means black. On any other kind it is `V_SHAPE` |
| `direction` | `"left"`, `"right"`, `"up"`, `"down"` | `whip` and `wipe` only; absent means `left`. On any other kind it is `V_SHAPE` |

The sum of an item's `transition_in.duration` and `transition_out.duration` is at most its `duration`. A fade multiplies opacity from 0 to 1 (in) or 1 to 0 (out), linearly. A slide moves the item from fully outside the frame to its position (in) or the reverse (out), with ease-out for in and ease-in for out. The formulas of `zoom`, `whip`, `dip` and `wipe` are in SDD-004 §3.2.

Keyframes animate a property over the item's duration:

```json
"keyframes": {
  "scale": [
    {"t": 0,  "value": 1,   "easing": "ease_out"},
    {"t": 30, "value": 1.2}
  ]
}
```

| Element | Rule |
| --- | --- |
| Properties | `x`, `y`, `scale`, `rotation`, `opacity`, and `volume` for items with audio; for clips also the colour properties (`brightness`, `contrast`, `saturation`, `temperature`, `tint`, `hue`) and the crop sides `crop_left`, `crop_top`, `crop_right`, `crop_bottom` (0 to 1); for an item that has a `mask` also `mask_x`, `mask_y` (0 to 1), `mask_width`, `mask_height` (0.001 to 1) and `mask_feather` (0 to 200, a whole number once drawn). A document with a `mask_*` key and no `mask` is `V_KEYFRAMES` |
| `t` | frame relative to the item's `start`, 0 to `duration` |
| `value` | a number valid for the property |
| `easing` | `"linear"` (default), `"ease_in"`, `"ease_out"`, `"ease_in_out"`, `"hold"` or `"bezier"` (epic 31, RF-080); applies from this keyframe to the next. A document written before `bezier` existed has none of it and opens unchanged: a missing easing is linear |
| `bezier` | array of four numbers `[x1, y1, x2, y2]`, present exactly when `easing` is `"bezier"` (otherwise `V_KEYFRAMES`): the two inner control points of a cubic Bezier curve from (0, 0) to (1, 1), as in CSS `cubic-bezier`. `x1` and `x2` are from 0 to 1, so time never runs backwards; `y1` and `y2` are from -2 to 3, so a curve can overshoot or pull back. The commands round the numbers to 3 decimals. The curve is evaluated only by the core (SDD-004 §3.1); an executor receives the sampled values. The commands write the named presets of SDD-002 C.75 as their four numbers, so a curve made from a preset stays editable |
| Ordering | strictly increasing `t` within a property; at most 100 keyframes per property |

When a property has keyframes they define its value: before the first keyframe the first value holds, after the last the last value holds, and the item's static field for that property is ignored. The exact interpolation formulas are in SDD-004. A curve that overshoots can take the interpolated value outside the range of the property (an opacity of 1.1, a crop side of -0.05): the plan keeps the sampled value inside the range of the property, so no executor sees an invalid number and the stored keyframes stay valid (SDD-004 §3.1).

### 3.9 Project fonts

| Field | Type | Meaning |
| --- | --- | --- |
| key | string | the family name used in styles |
| `files` | array of `{"weight": int, "hash": "sha256:..."}` | font files, stored in the workspace `fonts/` directory by hash |

The weights of the bundled families are those of `renderer/fonts/FONTS.md`: for example Anton ships 400 only, so a style with `font_family` Anton needs `font_weight` 400. User fonts are a feature of the brand kit (RF-053); the `fonts` map holds them. The rules of an entry:

- the key must not be the name of a bundled family (`V_FONT`);
- `files` has at least one entry, each `weight` is 100 to 900 in steps of 100, and no weight appears twice in one family (`V_FONT`);
- each `hash` is `sha256:` and 64 lower-case hex characters (`V_SHAPE`);
- the family and the weight a style uses come from this map and the `weight` of each file, never from the name table inside the font file; `V_FONT` accepts a style whose family is bundled or a key of this map, and whose weight is one the family has.

A document that was valid with an empty map stays valid. Adding entries to the map does not change `schema_version`. The commands `font.add` and `font.remove` (SDD-002 B.11) edit the map; a font file is stored by hash before `font.add` names it.

### 3.10 Template fields

Slot, on an item:

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `name` | string matching `[a-z][a-z0-9_]{0,39}` | required | unique in the document |
| `kind` | `"media"`, `"text"`, `"caption"` | required | must match the item type: `media` on `clip` or `audio`, `text` on `text`, `caption` on `caption` |
| `description` | string, up to 200 characters | `""` | tells a person or an agent what to put there |
| `required` | boolean | true | |
| `duration_policy` | `"fit"` or `"stretch_timeline"` | `"fit"` | media slots only (ADR-0022) |
| `filled` | boolean | false | |

In a template document a `clip` or `audio` item with an unfilled media slot has `asset` equal to the reserved value `"ast_placeholder"`, which is the only case where `asset` may be missing from `assets`.

TemplateInfo, at the top of a template document: `{"description": string, "colors": {"<name>": colour}, "instance": bool}`. A colour slot is an entry of `colors`; styles refer to it with the string `"$<name>"` wherever a colour is accepted.

`instance` (boolean, default false, omitted when false) tells a **template draft** from an **instance**. A draft is a document being authored as a template: its slots are open by design. An instance is a project made from a template (`TemplateInstantiate`, SDD-003): the instantiate path writes `template.instance: true` and keeps the `template` member so that the placeholder and the `"$name"` colours stay valid. The placeholder is valid in both (`V_ASSET_REF` depends only on the `template` member being present). Lint tells them apart: `L_SLOT_UNFILLED` is exempt on a draft and an error on an instance, so export is blocked until every required slot is filled (SDD-003 section on lint). A slot with `required: false` may stay on the placeholder in an instance: lint stays quiet and the plan skips its item (no layer, no audio source), so the starters export with their optional slots empty. `template.set_info` keeps the flag. Adding the field is an optional addition with a default that preserves the old behaviour, so `schema_version` stays 1.

## 4. Invariants

`core/timeline.Validate(doc)` returns every violation, each with a code, the path of the offending value and a message. `apply` never produces a document that violates one. Codes are stable.

| Code | Invariant |
| --- | --- |
| `V_SCHEMA_VERSION` | `schema_version` is one this binary supports |
| `V_SHAPE` | the document matches the JSON Schema (types, required fields, enumerations, ranges) |
| `V_ID` | every identifier has the right prefix and form, and each map key equals the object's `id` |
| `V_TRACK_ORDER` | track `order` values are valid and unique |
| `V_ITEM_TRACK` | each item's `track` exists and accepts the item's type |
| `V_ITEM_RANGE` | `start` is at least 0, `duration` at least 1, and the item ends at or before frame 108,000 |
| `V_OVERLAP` | no two items on the same track occupy a common frame |
| `V_ASSET_REF` | `asset` exists, or is the placeholder in a template, and its kind suits the item: `clip` uses video or image, `audio` uses audio or a video with audio |
| `V_SOURCE_RANGE` | the item's source range lies inside the asset (section 3.5) |
| `V_SPEED` | speed is between 1/4 and 4; a `speed_curve` has 2 to 8 points that meet the rules of its field and `speed` is its mean |
| `V_FADES` | `fade_in + fade_out` is at most `duration` |
| `V_TRANSITIONS` | transition durations sum to at most `duration` |
| `V_KEYFRAMES` | keyframe rules of section 3.8 hold |
| `V_WORDS` | caption word rules of section 3.7 hold |
| `V_MARKERS` | marker rules of section 3.4 hold: at most 200, each frame inside the item, frames strictly increasing; the same for the `markers` of the document, whose frames lie from 0 to the frame limit |
| `V_FONT` | every `font_family` and weight exists in the bundled set or in `fonts`; no key of `fonts` is a bundled family and no family repeats a weight (section 3.9); the effective weight (the given one, else 700) must be one the family ships, as listed in `renderer/fonts/FONTS.md` and kept in `timeline.BundledWeights` by a test |
| `V_SLOT` | slot names are unique and each slot kind matches its item type |
| `V_COLOR_REF` | every `"$name"` colour reference exists in `template.colors` |
| `V_LIMITS` | at most 50 tracks, 500 items, 200 assets and 5,000 caption words in the document |

The limits bound the cost of every operation and are well above the supported project size of NFR-009.

## 6. Versioning and migration

1. `schema_version` is an integer that increases by one for every incompatible change: a removed or renamed field, a changed meaning, a tightened constraint.
2. Adding an optional field with a default that preserves the old behaviour does not change `schema_version`. Older binaries keep it through the unknown-field rule.
   `blur`, `filter`, `filter_amount`, `markers`, `frame_delays` and the `fonts` entries were added under this rule: all are optional with a default that preserves the old behaviour, so `schema_version` stays 1 and no `v1to2` exists. A document saved by an earlier binary validates unchanged. `chroma_key`, `blend` and `mask` (VV-015), `flip_x`, `flip_y`, `disabled`, `temperature`, `tint`, `hue` and `denoise` (TASK-0233), `voice` (TASK-0254) and the document `markers` (VV-035) are added under the same rule: optional and absent by default, so `schema_version` stays 1. The track fields `locked`, `solo` and `volume` (VV-036) follow the same rule.
3. The chain lives in the package `core/timeline/migrate` (standard library only, no document type, so `timeline` can call it before typing a document). For each version step there is one pure function `func v1to2(doc Doc) (Doc, error)` over the decoded JSON (`Doc` is `map[string]any`, numbers as `json.Number`), registered in the `registry` table of `migrate.go`; `migrate.Migrate` chains the steps from the document's version to `migrate.Current`, and `timeline.Decode` calls it first through `timeline.Migrate`, which turns its error into a `V_SCHEMA_VERSION` or `V_SHAPE` violation. An `init` check panics when a version between 1 and `Current` has no step.

   **To add a version:** raise `migrate.Current` (and nothing else in the constant: `timeline.CurrentSchemaVersion` follows it), write `vNtoN+1`, register it, copy the valid examples to `testdata/versions/vN+1/`, add every new fixture path to `testdata/versions/MANIFEST.txt`, and regenerate the schema.
4. Each version has a fixture directory `core/timeline/testdata/versions/vN/*.json` whose files are never deleted; `MANIFEST.txt` in `versions/` lists them and `TestFixturesNeverDeleted` fails when one disappears. The migration test loads every fixture of every version, migrates it to the current version and validates it.
5. Decoding a document whose `schema_version` is higher than the binary supports returns `V_SCHEMA_VERSION` with both numbers and the instruction to upgrade the program. Nothing is written.
6. Templates are timeline documents and migrate through the same functions.
7. Storage keeps the pre-migration document as a backup (SDD-005).

## 9. OpenTimelineIO exchange

RF-065 (ROADMAP task P3-ENG-004). `core/otio` converts between this document and an OpenTimelineIO (`.otio`) file. It is pure Go over bytes: it imports neither `os` nor `net`, so it cannot open a file or a connection.

**Export** (`otio.Export(doc) (bytes, []Lost, error)`). The output is deterministic JSON (keys sorted, two-space indent):

| Document | OTIO |
| --- | --- |
| project `name` | `Timeline.1` `name`; the tracks are one `Stack.1` |
| track | `Track.1`, `kind` `Video` (visual) or `Audio`, `name`; the stack lists tracks bottom first (descending `order`) |
| `clip`, `audio` item | `Clip.2` with `name`, `source_range` (`source_in` and `duration` in project frames at the project rate; an image starts at 0) and an `ExternalReference.1` whose `target_url` is the asset `name` (a relative name, never a URL) |
| time between items | `Gap.1` with its `source_range` |
| `fade` in or out | `Transition.1` of type `SMPTE_Dissolve` next to the clip: `in` writes `in_offset` 0 and `out_offset` the duration, `out` the reverse |
| `markers` | `Marker.2` on the clip: `name` the label, `marked_range` start at `source_in + frame`, duration 0 |
| properties OTIO has no field for | `metadata.vukem` of the `Clip.2` (VV-025): `properties`, an object with the name and value of the document for each one that differs from its default: `x`, `y`, `scale`, `rotation`, `opacity`, `volume`, `audio_muted`, `fade_in` and `fade_out` (frames), `brightness`, `contrast`, `saturation`, `fit`, `crop`, `filter`, `filter_amount`, `blur`, `chroma_key` (the object of the item), `speed` (`{num, den}`), `reverse` (true only), `freeze` (true only; an import cannot restore it, because `item.freeze_frame` splits a clip, and reports `freeze frame` as lost), `hsl`, `wheels` and `curves` (the values of the item, restored by `clip.set_color` and checked with the rules of SDD-001 §3.5 at `Parse`), `lut` (`{asset, intensity}`; the asset is not part of the file, so an import reports `lookup table` as lost), `speed_curve` (list of `{t, speed: {num, den}}`), `keyframes` (the object of the item: per property a list of `{t, value, easing}`, plus `bezier`, the four numbers, when the easing is `bezier` (epic 31); an import refuses the list of a property whose curve is missing or not valid, as for any bad keyframe) and `slot` (`name`, then `description`, `required` (false only), `duration_policy` (not `fit`) and `filled` (true only)). Written only when there is one |
| `text` item | a `Gap.1` with the item's `name` and `source_range` (VV-025); `metadata.vukem` holds `text`, `style` (the style object of the item) and `properties` (`x`, `y`, `scale`, `rotation`, `opacity`, `keyframes`, `slot` as above). Other tools see a gap; `caption` and `shape` items are still only the time they take |
| `hidden`, `muted`, `magnet` of a track | `metadata.vukem` of the `Track.1` (`hidden`, `muted`, `magnet`, true only); an import sets them back with `track.update` |

The `vukem` metadata is ignored by other OTIO tools and read back by Vukem, so a file written by Vukem and imported by Vukem keeps these properties. Ids, hashes and `order` strings are not written (an import makes new ids). The markers of the document (VV-035, frames from the timeline start) are written twice: in `metadata.vukem.markers` of the timeline (`{frame, label?}`, exact) and as native `Marker.2` objects of the stack (`marked_range` start, the label as `name`), so that other tools see them; they are not in the lost list. Everything the file cannot carry is returned in `[]Lost`, which still lists the properties above because another tool will not see them (`id`, `name`, `feature`) and never dropped silently: `text`, `caption` and `shape` items (their time stays as a gap; each is also kept in the metadata of that gap), `keyframes`, `speed`, colour adjustment, filter and blur, framing (`fit`, `crop`), transform and opacity, audio settings (`volume`, `audio_muted`, fades), template slot, transitions other than `fade` (also kept in the metadata), a hidden track, a muted track, a track with `magnet`, a freeze frame, a lookup table, advanced colour (`hsl`, `wheels`, `curves`), a caption style, and a clip whose asset is the placeholder.

**Import** (`otio.Parse(bytes)` then `Import.Operations(assets, newID)`). Import returns a batch of command operations, not a document, so it goes through `Apply` and its undo rules. `Parse` reads `Timeline.1` with a `Stack.1`; each `Track.1` of kind `Video` or `Audio` becomes `track.add` (bottom track first, each at `position: "top"`), each `Clip.2` with a `source_range` becomes `clip.add` or `audio.add` (and `item.rename` for its name), `Gap.1` advances the cursor, and a `SMPTE_Dissolve` becomes `item.set_transition` with `kind: "fade"` on the clip after it (`out_offset`) and on the clip before it (`in_offset`). Times convert to the file's frame rate, taken from the first `source_range`, which must be an integer rate or n/1001 (the caller creates the project at `Import.FPS`). Names are cut to 60 (track) and 120 (item) characters. What the batch cannot carry is listed in `Import.Lost`: nested stacks, tracks of another kind, effects, transitions of another type, clips with no usable `source_range`, and a clip whose reference has no asset in `assets`. Nesting deeper than 64 levels is an error (`ErrInvalid`).

**Properties from `metadata.vukem`** (VV-025). A clip with `properties` also gets, after `item.rename`, the commands that restore them: `item.set_transform` (`x`, `y`, `scale`, `rotation`, `opacity`), `clip.set_blend` (`blend`, a clip or a text item), `clip.set_mask` (`mask`, a clip or a text item), `clip.set_flip` (`flip_x`, `flip_y`, a clip or a text item), `item.set_enabled` (`disabled`, any item), `clip.set_color`, `clip.set_framing`, `clip.set_filter`, `clip.set_blur`, `clip.set_chroma_key` and `item.set_audio` (`volume`, `fade_in`, `fade_out`, `audio_muted`), then one `keyframe.set` per keyframe (at the absolute frame, in time order; a property whose first keyframe is after the start gets the extra keyframe at the start that `keyframe.set` adds, removed again with `keyframe.remove`), then `slot.mark` and, for a filled slot, `slot.fill` (a text slot with its text, a media slot with `fit` with the same asset and `source_in`; a filled media slot with `stretch_timeline` is reported as lost, because filling it again would move other items). An audio item keeps `volume`, the fades, `speed` and volume keyframes only. `speed` (or, with a `speed_curve`, `clip.set_speed` with the `curve` and the clip added for the mean speed) comes right after the clip is added, before anything is animated, and `reverse` is a second `clip.set_speed` after the trim to the duration (trimming the end of a reversed clip moves `source_in`): the clip is added with the source length that `clip.set_speed` turns back into the duration of the file (set_speed rounds up), and trimmed to the duration when no length does. A `Gap.1` whose `metadata.vukem` has `text` becomes `text.add` (with `style`) at the position of the gap, then `item.rename` from the gap name, `item.set_transform`, the keyframes and the slot; a text whose `text` is empty or over 2000 characters, or whose `style` is not valid, is reported as lost and left as a gap. A font family that is not bundled (project fonts are not known to `Parse`) is reported as lost and dropped from the style with its weight, so that the batch still applies. A slot name used twice in the file is reported and left out the second time. The markers of the document come back as `marker.add` (`at` in frames, `label`), first in the batch: those of `metadata.vukem.markers` of the timeline when it has any, otherwise the native markers of the stack. A marker with a frame outside the timeline, a label over 60 characters, a frame that is already marked, or over the 200th is reported as `timeline marker ...` and left out. The markers of a clip (`Marker.2` in the `markers` of the `Clip.2`, written at the source frame of the item plus the frame of the marker) come back as `marker.add` with `item_id` (TASK-0254), last for that clip, at the position of the clip plus the frame (the marked position minus the start of the `source_range`); a marker outside the clip, a label over 60 characters, a frame that is already marked, or over the 200th is reported as `marker of clip ...` and left out. A track with `hidden` or `muted` gets `track.update` (`hidden` for a visual track only). The metadata comes from a file nobody vouches for, so each value is checked against the range of its command at `Parse`: a value that is not valid (wrong type, out of range, an unknown filter) is added to `Import.Lost` as `vukem property <name> is not a valid value` and left out, and the rest of the batch still applies. Caption and shape items and transitions other than `fade` are not restored (shape items need their own metadata and commands). `blend` (VV-015) is written as a property of a clip and of a text item (in the gap metadata); "blend mode" is no longer in the lost list, and a `blend` that is not one of `multiply`, `screen`, `overlay` or `add` is reported as not valid. `mask` (VV-015) is written the same way, an object with `shape`, `x`, `y`, `width`, `height`, `feather` and `invert` (omitted when false), and read back by `clip.set_mask`; a value that is not valid (unknown shape, a fraction or a feather out of range, a feather that is not a whole number) is reported as `vukem property mask is not a valid value`.

**Media references are never opened** (T-10, T-11, SDD-007 §7.2). Each distinct `target_url` is returned in `Import.Media` as `candidate` or `unresolved`. It is `unresolved`, with a reason, when it is empty, has a control character, begins with two backslashes, `//` or `\??\`, or has a URL scheme of two or more letters (`http:`, `file:`, `smb:`, `data:`, `concat:`); a single-letter drive (`C:\`) is not a scheme. A `candidate` is a local path returned to the caller, which must pass it through the path rules of `MediaImport` before importing the file and then supplies the asset id in `assets`. Nothing in `core/otio` fetches or opens either kind.

**Through the service (P3-SRV-005).** `ProjectOtioExport` (`GET /projects/{id}/otio`) runs `otio.Export` on the head revision and returns `{project_id, revision, file_name, content, lost[]}`, `file_name` being the project name made safe plus `.otio` and `content` the file text; nothing is written to disk. `ProjectOtioImport` (`POST /projects/{id}/otio`, `{path, base_revision, dry_run?}`) reads the file at `path` with the import path rules of `MediaImport` (SDD-007 §7.1), refuses a file over 16 MiB with `E_PAYLOAD_TOO_LARGE`, a file that is not an OTIO timeline and a frame rate other than the project's with `E_VALIDATION`, matches each `target_url` to an asset of the project by name (the whole `target_url` or its last path segment, never opening it), and applies `Import.Operations` as one `Edit` batch (the media must already be in the project: an asset is found by its name, so import the files with `MediaImport` first; an import into a new project places no clip and says so in `text`) (so it is one undo step, the actor is recorded and every rule of the command core holds). A file that needs more than 200 operations is `E_PAYLOAD_TOO_LARGE` with the hint to split the timeline. The result carries the `edit` result, `unresolved_media[]` (`ref`, `status`, `reason`: every reference that is not a candidate, plus candidates with no asset of that name) `matched_media[]` (`ref`, `asset_id`, `matched: "by_name"`: every reference answered by an asset of the same name, because the file carries no content hash) with one entry in `warnings[]` saying so when it is not empty, and `lost[]` (`Import.Lost` plus the clips the batch left out). A file with nothing to import is `E_VALIDATION`. `text` reads `imported N operation(s)` when the batch was applied and `would import N operation(s)` for a `dry_run`.
