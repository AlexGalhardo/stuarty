# PRD-004: The creator platform

- Status: Accepted (2026-11-18)
- Depends on: author decisions D-047 to D-052, D-057 to D-064, D-071, D-075, D-077 to D-079; research notes `web/01-engine-imagem` to `web/07-stack-desktop-web-self-hosted`
- Implemented by: the epics of `docs/plans/` (index and traceability in `docs/plans/00-roadmap.md`); each epic writes the specification of its domain before code. Decisions: ADR-0031 to ADR-0047

Stuarty: create, edit, manage and publish your content in one place. This document covers everything around the video editor of [PRD-001](001-video-editor.md): the project as a production, the dashboard, assets, image editing, writing, AI providers, the agent chat, memory, skills and prompts, and publishing. Agent requirements common to every domain are in [PRD-002](002-agent-operability.md); installation and security of the installation are in [PRD-003](003-distribution-and-docs.md).

## 1. Problem

A creator uses dozens of tools and has to master, alone, the orchestration of AI agents (skills, context, long-term memory), the craft of audio and video, and the method to produce consistently. The files of one production are spread over folders and services, the same video is uploaded by hand to each network, and what worked is remembered by nobody. Tools that automate one step exist and are good; none holds the whole cycle in one local place.

## 2. Users

| User | What they do | What they need |
| --- | --- | --- |
| The independent creator | Publishes on YouTube, Instagram, X, Reddit, TikTok, Kwai, blogs and sites | One place from the idea to the published post, with the know-how built in |
| The AI agent | Claude Code, Codex, OpenCode and others, in a terminal or hosted in the chat | Everything a person does in the UI, through the API, the CLI and MCP |
| The author of the project | The first user: becomes a creator by using Stuarty | The first complete flow working on his own machine |

## 3. The first complete flow

A person opens Stuarty, creates a project, answers the guided briefing and, with their own agent in the chat panel, produces a short vertical video: script, assets (imported or generated), the edit with captions, a thumbnail made in the image editor, the exports in each network's format, and the publication to YouTube and Instagram after their approval. What was learned goes to Memory.

It is done when the author has published ten real videos using only Stuarty, noting the time of each step, and when a small-model agent completes the flow without help in at least 9 of 10 runs.

## 4. Functional requirements

### 4.1 Projects and briefing

| ID | Requirement |
| --- | --- |
| RF-300 | A project holds a production: its briefing, scripts and texts, the assets it uses, one or more timelines, image documents, output pieces and publications (ADR-0039) |
| RF-301 | A new project starts with a guided briefing that finds out what the user wants to make: the kind of piece (short video, long video, carousel, single image, story, blog post, ad), the destinations, the format and duration, the goal, the audience and a reference |
| RF-302 | The answers of the briefing are stored in the project as text that a person can edit and an agent can read |
| RF-303 | A project shows the state of its production: what exists, what is missing, what waits for approval, what was published |
| RF-304 | A workspace created before this model opens with each former project as a project holding one timeline |

### 4.2 Dashboard

| ID | Requirement |
| --- | --- |

| RF-312 | Every section is the same page in the browser and in the desktop application (ADR-0041), in English and in Brazilian Portuguese |

### 4.3 Assets

| ID | Requirement |

| RF-334 | Filters: blur, sharpen, noise, vignette and pixelate |
| RF-335 | Masks by shape and by alpha, and a clipping mask |
| RF-336 | Templates with named slots for images, text and colours; a thumbnail template is filled in one batch |
| RF-337 | Export to PNG, JPEG and WebP, with presets per destination (for example a YouTube thumbnail, an Instagram post, a blog cover) |
| RF-338 | The picture shown in the editor is the exported file, drawn by the same renderer |

| RF-340 | A background can be removed, an area inpainted, an image upscaled or expanded through a provider; the result is an ordinary image layer with its origin recorded |
| RF-341 | The UI has a layer panel, a canvas with handles and an inspector; every operation of the catalogue can be performed from it |
| RF-342 | The brand kit of the workspace (logo, colours, fonts) is available to image documents and their templates |

### 4.6 AI providers and generation

| ID | Requirement |
| --- | --- |
| RF-360 | A provider is connected in one of four ways: an API key, Sign in with ChatGPT, the OpenRouter OAuth flow, or the user's local agent (ADR-0036) |
| RF-361 | Generation of text, images, voice and video is available from the UI and from every agent surface |
| RF-362 | Every generation is a job with an estimated cost shown before it runs and the real cost recorded after |
| RF-363 | Cost ceilings per day and per project stop further generation with a clear message; a costly generation waits in the approval queue (ADR-0032) |
| RF-364 | The models offered by a provider are read from the provider, not fixed in the product |
| RF-365 | The product never offers a subscription login that a provider forbids for third-party applications, and integrates no service without an official API |

## 5. Non-functional requirements

| ID | Requirement |
| --- | --- |
| NFR-060 | All files, tokens, credentials and authorizations stay on the user's machine or on the user's own server |
| NFR-061 | An image document of 4,000 by 4,000 pixels with 30 layers is composed for the preview within 100 ms after an edit and exported within 2 s on the reference machine |
| NFR-062 | The same image document and assets produce identical exported files on two runs on the same machine |
| NFR-063 | A change of rule on one network or one provider is fixed in one adapter, with no change in another |
| NFR-064 | Each connector has contract tests against recorded responses, and a manual check with a real account before it is called done |
| NFR-065 | Every section of the dashboard is operable by keyboard and meets WCAG 2.2 level AA for contrast, focus and names |
| NFR-066 | The product and its skills are written so that a small-model agent can complete the first complete flow without help |

## 6. Success metrics

1. The author publishes ten real videos using only Stuarty and records the time of each step.
2. A small-model agent completes the first complete flow without help in at least 9 of 10 runs.
3. The number of tools and of manual file uploads the author needs to publish one video falls to one tool and zero uploads.

## 7. Out of scope

| Feature | Why |
| --- | --- |
| Midjourney | No official API, and its terms forbid automation (ADR-0036) |
| A subscription login of a provider that forbids it in third-party applications | The provider's rules (ADR-0036) |
| An agent built into the product | The chat hosts the user's own (ADR-0037) |
| Public posts on TikTok | Its API allows only private posts from an unaudited application, and the audit excludes private use (ADR-0035) |
| A central Stuarty service, an official OAuth application | Self-hosted (ADR-0034, ADR-0035) |
| Metrics of published posts, Reddit and Kwai | Later epics (ADR-0035, ADR-0046) |
| Painting and brushes, CMYK, 16 and 32 bits per channel, HDR, RAW | Outside the most used fifth of an image editor (ADR-0038) |
| A stock media library | Licensing (author decision D-014) |
| Telemetry | Author decision D-016 |
