# ADR-0005: Timeline model: absolute positions, tracks, typed items

- Status: Accepted (2026-11-14); what a project is, is amended by [ADR-0039](0039-project-as-production-container.md) (2026-11-18): this model becomes the timeline inside a project
- Deciders: architect
- Links: engine §3, post-mortems §6, §7, SDD-001

## Context

OpenTimelineIO and MLT model a track as a sequence with explicit gaps; Shotstack and OpenCut give each item an absolute start and length. Transitions are separate items in OTIO and MLT and a clip property in Shotstack. Olive accumulates crash reports in undo involving transitions between two clips. OpenCut stores captions as ordinary text and a production user reported five frictions because of it.

## Decision

1. A project has an ordered list of **tracks**. Track order is by a fractional index string, so inserting between two tracks renames nothing. The track listed first in every view is the top layer.
2. An **item** belongs to one track and has an absolute `start` and `duration` in frames. Items on the same track do not overlap. Gaps are simply absence; there is no gap object.
3. Items are typed: `clip` (video or image from an asset), `audio`, `text`, `caption`, `shape`. Each type has its own properties; common ones are `id`, `track`, `start`, `duration`, `keyframes` and the flat `x`, `y`, `scale`, `rotation`, `opacity` (there is no `transform` object, SDD-001 §3.4).
4. A **caption** item carries `words[]` with per-word start and duration in frames relative to the item, plus a style. A caption track's style can be set for all its items in one command.
5. A **transition** is a property of an item's entry (`transition_in`) or exit (`transition_out`), with a kind from a fixed list and a duration. A crossfade between two clips is two clips on adjacent tracks with opposite transitions over the same frames, which a helper command sets up.
6. Ripple editing is a command that emits several moves, not a property of the model.
7. Projects, assets, tracks and items have a stable identifier with a type prefix (`prj_`, `ast_`, `trk_`, `itm_`), generated by the caller of `apply`. No track or item is addressed by position. A keyframe is addressed by item, property and frame; a caption word by item and index.
8. Nested timelines are out of scope; the schema does not forbid adding them later.

## Alternatives

- **Sequential tracks with gap objects.** Moving one clip changes the position of all that follow, so a command only makes sense relative to the current order. Bad for idempotent commands and for two actors editing at once.
- **Transitions as separate items referencing two clips.** More expressive; creates cross-references that undo must rebuild, the area where Olive crashes.
- **No tracks, only layers per item.** Simpler JSON; loses the track as the unit a person and a caption style work on.

## Consequences

Positive: "move item X to frame 300" has the same effect whatever else happened, which suits last-writer-wins per object (ADR-0006).

Positive: deleting an item deletes its transitions; no dangling references.

Negative: a crossfade needs two tracks. The helper command hides this; the lint reports a transition with nothing under it.

Negative: non-overlap on a track is an invariant every move must check; the error must say which item is in the way and where the next free frame is.
