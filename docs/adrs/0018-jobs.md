# ADR-0018: Long work runs as jobs with their own state table

- Status: Accepted (2026-11-14); scheduled and approved jobs are added by [ADR-0046](0046-publishing-scheduler-and-blog-destinations.md) (2026-11-18)
- Deciders: architect
- Links: post-mortems §9, vukem practices, VF-001 and VF-002 in `vukem-feedback.md`, ADR-0008, SDD-005

## Context

Ingest, transcription and export take seconds to minutes. Other editors fail here in ways an agent cannot see: OpenCut's export stuck at 5% with no error, FreeCut reporting "Export complete" for a file without audio, Remotion rendering wrong frames silently. The stack draft listed river or asynq. vukem has a queue with a `database` driver, at-least-once delivery, retries and timeouts, but no progress and no cancellation of a running job (VF-002), and its default table name `jobs` collides with a domain table (VF-001). The Studio already worked around both with its own job row, a conditional claim and `Retries(0)`.

## Decision

1. Jobs are dispatched through vukem's queue with the `database` driver. No river, no asynq, no Redis. The queue tables are configured as `queue_jobs` and `queue_failed_jobs`.
2. The product keeps its own table `jobs` with: kind (`ingest`, `transcribe`, `export`, `frame`), project, input, state (`queued`, `running`, `succeeded`, `failed`, `cancelled`), progress (0 to 1), a short message, a typed error, the result, the actor and timestamps.
3. The queue payload is only the job identifier. A handler **claims** the job with a conditional update, so a redelivered message does nothing. Handlers run with `Retries(0)`.
4. A handler reports progress by updating the row; each update is also an event on the project's stream (ADR-0017).
5. Cancellation sets a flag on the row; the handler checks it between steps and cancels the context of the running FFmpeg process, which `contrib/engine` kills with its process tree.
6. A job only becomes `succeeded` after its output passed verification. For an export: streams present, duration within one frame of the timeline, dimensions, pixel format and `faststart`.
7. Concurrency limits are enforced before queueing: at most a configured number of exports running per workspace and per API key. A full queue answers with a retryable error that names the running jobs.
8. In the in-process mode of the CLI, the same handlers run synchronously in the calling process (ADR-0008).

## Alternatives

- **river or asynq.** Need PostgreSQL or Redis, which D-003 excludes.
- **Goroutines without a queue.** No survival across a restart and no limits.
- **Wait for vukem to add progress and cancel.** The gap is reported (VF-002); the product cannot wait for it.

## Consequences

Positive: an agent always gets a truthful, typed state; a failed export is never reported as success.

Positive: no extra service to run.

Negative: job state is duplicated between vukem's queue table and ours; ours is the one clients read.

Negative: if vukem later ships progress and cancellation, this table becomes partly redundant and should be reconsidered.
