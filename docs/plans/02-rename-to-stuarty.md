# 02: Rename the code to Stuarty, with a workspace migration

## Goal

The product is called Stuarty everywhere a person or an agent meets it: the command they type, the folder their data lives in, the variables they set, the image they pull, the documentation they read. Someone who already used Vukem Video keeps their projects without doing anything.

## Context and related decisions

- ADR-0044 (the rename, in one epic, with a migration), ADR-0031, ADR-0047 (the vukem framework is not renamed).
- Author decisions D-047, D-068. PRD-003 RF-200, RF-208, RF-221.
- The former name is in about 1,190 tracked files.

## Scope

- The Go module path (`github.com/AlexGalhardo/vukem-video` to `github.com/AlexGalhardo/stuarty`) and every import.
- The binary (`vukem-video` to `stuarty`), the desktop binary, the CLI help, the MCP server name and instructions, the generated agent documents.
- Environment variables (`VUKEM_VIDEO_*` to `STUARTY_*`), the workspace folder (`~/.vukem-video` to `~/.stuarty`), file names inside the workspace that carry the name, the bundle extension if it carries it.
- The container image name, the Dockerfile and its paths, the installers, `.config/`, `Taskfile.yml`, scripts, workflows (names and paths only).
- The specifications (SDD-000 first, then the others), the documentation site (both languages) and its generated reference, `README.md`, `AGENTS.md`, `CLAUDE.md` and `.agents/` (drop the notes that say the code still has the former name).
- The renderer crates (`vukem-renderer*`) and the embedded module name.

## Out of scope

- The vukem framework: its import paths, its name and its repository stay.
- `CHANGELOG.md` history and the text of past release notes.
- A new logo or visual identity.
- Moving the documentation site to a new domain (it is a setting of the author; the code takes the address from one variable).

## Technical design

- **Order:** names in `docs/sdds/000-shared-definitions.md` first (it is the source of the site reference), then code, then generated files, then prose.
- **Compatibility on first start** (`service/workspace`, `service/config`): if the new workspace folder does not exist and the former one does, make a backup and adopt it (rename in place when on the same volume, otherwise copy and verify, then leave a marker file in the old location). Record the migration in the workspace and print it once.
- **Environment variables:** read `STUARTY_X` first; when it is unset and `VUKEM_VIDEO_X` is set, use it and log one deprecation warning per variable per start. One table in `service/config` holds every pair, and a test walks it.
- **Stable surfaces:** MCP tool names, CLI command names and HTTP routes do not contain the product name and do not change; `web/contract/testdata/surface.txt` must be byte-identical before and after.
- **Golden files** that contain the name (agent documents, text formats, help output) are regenerated by their generators, never edited by hand.
- **The update feed and installers** keep an identifier that lets an installed Vukem Video find Stuarty as its update; if that cannot be kept, say so in the hand-off.

## Test strategy

- Unit: the variable fallback table; the workspace adoption in every case of task 4, on a temporary home.
- Contract: `TestSurfaceFrozen` unchanged; the tests that compare SDD-002, SDD-003 and SDD-007 with the code.
- End to end: the smoke test with the renamed binary; a workspace created by the release 0.29.0 binary opened by the new one (fixture built once by the intern and committed as test data).

## Acceptance criteria

1. `git grep -il "vukem[-_ ]\?video"` prints only `CHANGELOG.md`, the ADRs and documents that tell the history, the compatibility code of tasks 3 and 4 with its tests, and test fixtures of old workspaces.
2. `go build ./...`, `go vet ./...` and `task test` exit 0; `go test ./web/contract/ -run TestSurfaceFrozen` passes with `surface.txt` unchanged.
3. Starting the new binary with only a `~/.vukem-video` workspace (in a temporary home) adopts it, keeps every project, leaves a backup, and says so once.
4. Starting with `VUKEM_VIDEO_HOME` set and `STUARTY_HOME` unset uses that folder and logs one deprecation warning.
5. `task image:smoke`, `task site:build`, `task lint` and `bash scripts/smoke-e2e.sh` exit 0.
6. `stuarty version`, `stuarty mcp` and `stuarty serve` work; no command named `vukem-video` is built.

## Risks and mitigation

- **A missed reference breaks at run time, not at build time** (a path in a script, a variable in a workflow). Mitigation: acceptance criterion 1 is a grep with an explicit allowlist, written in the hand-off.
- **Losing a user's workspace.** Mitigation: backup before adoption, never delete the former folder, tests for every case.
- **Other branches conflict with almost every file.** Mitigation: this epic runs alone; nothing else starts before it is merged.
- **STOP** if a stable surface (`surface.txt`) would have to change, or if the update feed cannot keep an identifier across the rename.
